Plan 13 · Multplx

mx-doctor — One Command to Check Every Invariant

A read-only, idempotent health sweep of every system invariant — locks, liveness, worktrees, PIDs, queues, holds, run records, tools, symlinks — printed as one categorized OK/WARN/FAIL report. An optional --fix applies only the provably-safe remediations, using the same liveness proofs the watcher already trusts; everything else is report-only with the exact suggested command.

Phase 9 (post-port) Effort: Low-Medium Risk: Low Post-port improvement (maintainer request, 2026-07-27)

Overview

Multplx already knows how to check its own health — it just knows it in scattered places, at scattered times. Bootstrap (firstmate/bin/fm-bootstrap.sh) runs a rich probe pass, but only at session start, emitting structured lines its header documents precisely: MISSING: <tool> (install: <command>), MISSING_MANUAL: <tool> (instructions: <url>), NEEDS_GH_AUTH, FLEET_SYNC: <repo>: skipped|recovered|STUCK: <detail>, and TANGLE: <remediation> (the primary checkout stranded on a feature branch, with the exact restore command). The watcher (fm-watch.sh) checks its own singleton lock and heartbeat freshness — but only when a second watcher tries to arm. The guard (fm-guard.sh) checks the liveness beacon (state/.last-watcher-beat) — but only per turn, and only for the in-flight-tasks-without-watcher case. Recovery procedures live in skills (stuck-crewmate-recovery, bootstrap-diagnostics) as prose for an agent to follow.

What no single artifact provides is the maintainer's on-demand question: "is everything consistent right now, and if not, what exactly do I run?" After a crash, a laptop sleep, a force-killed session, or just weeks of accumulated state, the answer today is re-reading skills and spot-checking state/ by hand.

bin/mx-doctor.sh is that one command: a read-only sweep of every invariant the system depends on, one categorized report, deterministic exit code, and a --fix mode whose scope is a short whitelist of reversible cleanups grounded in proofs the codebase already trusts — fm-lock-lib.sh's "provably abandoned" decision procedure (lock exists + lsof shows no live holder + mtime older than threshold, with any uncertainty meaning NOT stale) and fm-wake-lib.sh's fm_pid_alive / fm_pid_identity (PID liveness with start-time+cmdline identity, so a reused PID never counts as the original process).

Design rule — reuse, don't re-derive

Doctor invents zero new liveness or staleness logic. Every "is this dead?" question is answered by the exact primitives the watcher and teardown already trust (mx-lock-lib.sh, mx-wake-lib.sh). And bootstrap's probes are not duplicated: the shared checks are extracted into a lib with a single owner, which both mx-bootstrap.sh (session-start, unchanged output contract) and mx-doctor.sh (on-demand, richer rendering) call. Two copies of a probe is how probes drift.

Goals & Non-goals

GoalsNon-goals
  • bin/mx-doctor.sh: idempotent, read-only by default, runs every check, prints OK/WARN/FAIL per check plus a summary.
  • Exit code reflects the worst finding: 0 all OK, 1 worst is WARN, 2 worst is FAIL.
  • --fix: applies only the whitelisted, reversible remediations; prints everything else as a recommended manual action with the exact command.
  • Extract the probes bootstrap and doctor share into bin/mx-probe-lib.sh — one owner, two callers.
  • Machine-readable twin: --json for scripting/CI.
  • Doctor never kills processes and never deletes task state, worktrees, or holds — in any mode. Those stay with their owners (mx-teardown.sh, mx-decision-hold.sh, the recovery skill).
  • Not a daemon, not scheduled, not wired into the watcher — purely on-demand.
  • Does not replace bootstrap's session-start diagnostics (they keep their exact output contract for the agents that parse them).
  • No auto-repair beyond the whitelist; no "--force" escape hatch.
  • Does not read the plan-12 journal for any decision (display-only context at most).

The --fix contract

Default mode makes zero mutations — enforced by test, not convention. --fix is a closed whitelist of exactly two remediations in v1: (1) clearing a provably-stale watcher lock, (2) pruning provably-orphaned wake-queue entries. Both are reversible (a cleared stale lock is re-created by the next watcher arm; a pruned orphan wake references a task that no longer exists), and both reuse the exact staleness/liveness proofs the watcher and teardown already trust — with the lib's fail-safe posture inherited verbatim: any uncertainty means no action, report only. Doctor never kills a process, never deletes task state, never tears down a worktree, never closes a hold. Every non-whitelisted finding prints the exact suggested command and the name of the owner that should run it.

The extraction: bin/mx-probe-lib.sh

Bootstrap keeps emitting its exact session-start lines (agents and tests parse them), but the probe logic — tool presence + version compatibility, gh auth, tangle detection — moves to a shared bin/mx-probe-lib.sh that returns structured results; mx-bootstrap.sh renders them in its legacy line format, mx-doctor.sh renders them as report rows. Naming note: mx-check-lib.sh is taken — upstream fm-check-lib.sh/fm-check-register.sh are the watcher's runnable-check registry, an unrelated subsystem — hence probe-lib. This extraction is the one genuinely risky edit in the plan (see Risks); bootstrap's behavior tests are the safety net.

Risks & open questions

Risk — the probe extraction (the one risky bit)

Refactoring a working bootstrap is the only edit here that can break existing behavior. Bootstrap's output lines are a parsed contract (session-start agents and mx-bootstrap.test.sh both consume them), and its probes have subtle branches — e.g. treehouse/no-mistakes-era version-compatibility reporting as MISSING, and the fleet-sync timeout wording. Mitigations: the extraction is its own commit with zero doctor code in it; acceptance is mx-bootstrap.test.sh green unmodified; where a probe is awkward to extract cleanly (fleet-sync's timeout plumbing), leave it in bootstrap and have doctor call a narrower probe — extraction scope follows safety, not symmetry.

Risk — --fix scope creep

Every future stale-state annoyance will lobby to join the whitelist ("doctor should just tear that down"). The contract is structural: the whitelist is a named list in one place, each entry must cite the pre-existing proof primitive it reuses, and the snapshot-diff test enumerates the exact paths --fix may touch — adding a remediation without extending the test fails CI.

Open question — WARN/FAIL severity boundaries

Which findings are WARN vs FAIL is a judgment call per check (a stale beacon with zero in-flight tasks is arguably OK, with in-flight tasks it's the guard's alarm case). v1 ships conservative defaults documented in docs/doctor.md; tune from real use rather than debating up front.

Open question — dispatch-age threshold

48h default for dispatch-queue-age is a guess. Make it a config knob (env or config file, consistent with how plan 07 exposes its headroom knobs) and revisit after a few weeks of live use.

Open question — compat-symlink retirement

Porting.md decision 10 says the Computer -> Multplx links "can be removed once no old session needs resuming." Doctor treats absent as OK and dangling as WARN — but should it eventually nudge removal once the links are old and unused? Deferred; report-only either way.

Implementation deviations

  • The completed plan-09 credential boundary supersedes this plan's older gh auth status assumption. Doctor verifies that gh is installed but does not require agent-context authentication, preserving credentialed delivery outside the agent environment.
  • The completed plan-07 implementation stores parked dispatch requests under state/.dispatch-queue/*.request, so dispatch-queue-age inspects those authoritative records rather than queued prose in data/backlog.md.
  • primary-tangle is rendered as its own named doctor check because tangle classification is part of the extracted shared probe contract.
  • The optional plan-15 visualization server record is accepted if present, but its absence remains healthy because plan 15 is not a dependency of this phase.
