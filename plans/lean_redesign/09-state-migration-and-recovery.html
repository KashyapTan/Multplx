Overview

The old vocabulary lives in private configuration, marker files, backend labels, pending replies, workflow snapshots and publication records. Migration must preserve identity and unfinished work without replaying old policy or silently changing an in-flight process.

Implementation steps

  1. Build fixture-first migration.Use Phase 02 mapping to classify each legacy file as unchanged, alias-readable, converted or archived. Add a version marker and an inspect/apply entry through the existing CLI, keeping new syntax labeled proposed until implemented.
  2. Exclude concurrent writers.Acquire the owning home lock and arrange a safe boundary for participating sessions. Preserve the durable queue and pending reply identities. Unavailable or newer homes remain untouched with a specific diagnostic.
  3. Publish repeatably.Back up affected owned records and publish atomic per-file changes with a resumable transaction record. Fault-test every boundary. Keep journals, status event history and immutable workflow snapshots intact.
  4. Handle old permissions as history.Never convert pending approval to approved, waived to passed, a receipt to landed, or yolo to merge rights. Preserve requested review evidence. Remove only provably Multplx-installed local denial/credential overlays, not unrelated user choices.
  5. Update producers and readers.Emit canonical new labels for new sessions; read legacy markers/aliases for the compatibility window. Route messages according to peer support. Keep task IDs, PR URLs and process identities stable. A10 explicitly permits recoverable worktree relocation and new internal lease identities after verified transfer; retain historical path/lease mappings and update all owning references.
  6. Reconcile recovery and cleanup.Retain singleton supervision, native-signal precedence, PR poll quarantine/retirement, AFK transfer and interrupted child behavior. A persistent sub-agent with an empty queue stays healthy. Never clean up unlanded work to complete a rename.
  7. Provide reversible rollout.Migrate an isolated copy first, compare semantic snapshots, then roll out home by home. Downgrading requires the matching backup and stopped writers; no blind reverse substitution or old binary over new state.
  8. Migrate inboxes, attempts and receipts safely.Extend fixture conversion to claimed/acknowledged events, waiting continuations, pending action receipts, current attempts and accepted brief revisions. Preserve stable task/message/correlation identities. An unbound legacy report stays historical or awaits reconciliation; it does not prove a new attempt completed.
  9. Reconcile replacement resources.Before reassigning a mutable resource, reconcile and stop or isolate the old process as required by A2. Test actual process ownership separately from stale-report rejection. Keep worktrees and artifacts available until disposition.
  10. Recover compact task context.Build startup summaries from the canonical projection with current objective, owner, brief, dependencies, questions and evidence pointers. Retain targeted detail retrieval and declare unavailable homes instead of replaying complete transcripts.
  11. Migrate project locations without moving repositories.Convert legacy flat managed-clone entries into Phase 02 identities while preserving task routes and ownership. Keep new discovery roots distinct from homes, validate external locations and retain missing records for repair. Audit persistent-home project provisioning and synchronization so adopted checkouts are not copied or maintained as owned clones.
  12. Transfer legacy resources without competing managers.Implement A10 migration from recorded Treehouse task/home paths using inert versioned metadata and Git inventory. Quiesce wrapper shells, preserve lease uncertainty, use recoverable Git moves where supported, and update every task/home reference. Unsupported transfers remain retained with a concrete continuation requirement.
  13. Migrate domain responsibility and parent bindings.Apply A11 role mapping based on existing charter responsibility, preserving children, routes, correlations and configuration. Reconcile interrupted transfers and coordinator replacement without cloning state authority or classifying every persistent agent as a coordinator.

Scale and recovery design review

Apply the accepted state and communication contract to legacy fixtures before finalizing migration. Task identity, attempt identity, accepted plan revision and role are separate fields; a compatibility reader must not pretend an old task-only report proves the current attempt completed.

Use compact task summaries for orchestrator restart and targeted detail retrieval for decisions. Define cancellation and reassignment so an old process cannot be mistaken for the new owner. Preserve its worktree until ownership is reconciled. Retain filesystem storage throughout the port; use resumable receipts and interruption tests for cross-record consistency. A database migration is out of scope.

  • Coordinating, non-coordinating and ambiguous legacy homes migrate truthfully; live children and undelivered outcomes survive restart and attempted retirement.
