Overview

Current task kind, delivery mode and yolo values are consumed by launch, brief generation, snapshots, teardown and persistent-home provisioning. The rename must change that model, while retaining the useful difference between a task, an execution attempt and a persistent home.

Implementation steps

  1. Define the smallest normalized schema.Extend the current task/session records rather than introducing a second database. Identify canonical parent identity, home, runtime/session reference and persistence facts. Keep report-vs-change as an output choice, not a worker role.
  2. Map every old representation.Specify a versioned read mapping for delivery, scout, daemon, mode, yolo, registry entries and config files. Treat old yolo as inert for merge authority. Reject ambiguous conflicting records instead of picking a random identity.
  3. Remove role gates.Make direct work and delegation possible for any agent within its task. Remove blanket child-lifecycle refusal, no-project-write restrictions and mandatory scout promotion as a permission ceremony. Keep outcome changes explicit in the task record.
  4. Retain persistent operation.Use persistence and home ownership to select provisioning/restart behavior. Do not delete live homes, domain routes, idle sessions or leases because the daemon noun disappears. Sub-agents may delegate further without a special daemon class.
  5. Normalize launch and configuration.Introduce canonical sub-agent-facing names with the bounded aliases specified by migration. Preserve explicit harness/model/effort choices; do not replace dispatch profiles with a new policy engine or require capacity-ranking reasoning at every intake.
  6. Separate the migration boundary.Implement new readers and fixture conversions now; Phase 07 performs the home-level transaction. Keep incompatible writers from sharing a home. Bind every child to a resolvable parent and prevent cycles without limiting useful nesting depth by policy.

Test plan

  • Rust lifecycle, local-state and dispatch tests plus tests/mx-brief.test.sh, tests/mx-spawn-dispatch-profile.test.sh and tests/mx-spawn-batch.test.sh.
  • tests/mx-daemon.test.sh, tests/mx-daemon-safety.test.sh, tests/mx-daemon-harness-model-resolution.test.sh and tests/mx-shared-maintainer-inheritance.test.sh: retain persistence/configuration facts under the new names.
  • Legacy delivery/scout/daemon fixtures normalize to common sessions with the correct output and persistence; malformed, duplicate and conflicting identities refuse safely.
  • A report task and implementation task differ in requested artifact, not whether the sub-agent can delegate. Existing local-only projects remain usable without inventing a remote.

Documentation and instruction updates

Update configuration schema, CLI help, examples and task lifecycle docs with a precise legacy-to-canonical mapping. Mark proposed fields and command aliases as proposed until they are implemented.

Definition of done

  • One common sub-agent representation replaces role-specific permissions.
  • Persistent sub-agents preserve current isolated-home behavior and pinned configuration.
  • Parent/task/session distinctions are explicit enough for nested routing and recovery.
  • Legacy readers have tests and no yolo value grants agent merge rights.
Integration risk

A global actor-to-subagent replacement cannot distinguish wire tokens, user labels, service daemons and agent roles. Change semantic owners first; leave historical bytes and compatibility aliases to the migration phase.
