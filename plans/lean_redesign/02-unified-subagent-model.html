Keep a dedicated orchestrator and a common sub-agent lifecycle, with researcher, implementer, reviewer and scoped sub-orchestrator assignments.

Overview

Current task kind, delivery mode and yolo values are consumed by launch, brief generation, snapshots, teardown and persistent-home provisioning. The rename must change that model, while retaining the useful difference between a task, an execution attempt and a persistent home.

Implementation steps

  1. Define the smallest normalized schema.Extend the current task/session records rather than introducing a second database. Identify canonical parent identity, home, runtime/session reference and persistence facts. Record researcher/implementer/reviewer/sub-orchestrator as assignment metadata, separate from task output, persistence and execution placement. Implement the accepted task, execution-attempt and brief-revision semantics in A2, including message bindings and legacy unknowns.
  2. Map every old representation.Specify a versioned read mapping for delivery, scout, daemon, mode, yolo, registry entries and config files. Treat old yolo as inert for merge authority. Reject ambiguous conflicting records instead of picking a random identity.
  3. Simplify legacy role gates.Keep the main agent focused on conversation, research, synthesis, planning and coordination. Implementation and test-code changes belong to sub-agents. Remove blanket child-lifecycle refusal and mandatory scout promotion as a permission ceremony. Keep role reassignment, scope and outcome changes explicit in the task record.
  4. Retain persistent operation.Use persistence and home ownership to select provisioning/restart behavior. Do not delete live homes, domain routes, idle sessions or leases because the daemon noun disappears. Sub-agents may delegate further without a special daemon class.
  5. Normalize launch and configuration.Introduce canonical sub-agent-facing names with the bounded aliases specified by migration. Preserve explicit harness/model/effort choices; do not replace dispatch profiles with a new policy engine or require capacity-ranking reasoning at every intake.
  6. Separate the migration boundary.Implement new readers and fixture conversions now; Phase 09 performs the home-level transaction. Keep incompatible writers from sharing a home. Bind every child to a resolvable parent and prevent cycles without limiting useful nesting depth by policy.
  7. Implement filesystem transition primitives.Reuse atomic replacement and scoped locking to record stable operation intent, progress and completion for multi-record task/session transitions under A1. Define recovery and the authoritative commit point before adding consumers; keep journals and projections derived.
  8. Implement attempt and revision validation.Bind reports and evidence to current task, attempt and accepted brief identity under A2. Define nullable/non-applicable envelope fields and legacy unknowns. Replacement creates a new generation; a proven resume retains its existing identity. Preserve superseded evidence.
  9. Model schedulable work and shared views.Add dependency, priority, runnable/waiting and human-decision facts to the existing model, separate from active sessions and assignment role. Publish the versioned typed projection consumed by Phases 04-12 without making a snapshot a second store.
  10. Implement stable project and checkout identity.Extend the filesystem registry beyond flat mode lookup with validated local locations, aliases, optional remotes and managed/user-owned status. Bind each task/attempt/queued request to its selected project, checkout and starting revision. Publish discovery-facing schema for Phase 11; changing display context cannot retarget work.
  11. Bind allocation identity to the shared model.Add A10 allocation/lease generation, project/common-Git identity, exact path/base, task attempt and persistence facts to the existing filesystem schema. New immutable acquisition identities distinguish a reused path from its earlier owner.
  12. Represent domain and coordinator identity.Add A11 domain, root/parent/owner-home, scope revision and assignment generation to the common model. Keep persistence separate, validate acyclic lineage and define transfer identities for Phase 05.

Test plan

  • Rust lifecycle, local-state and dispatch tests plus tests/mx-brief.test.sh, tests/mx-spawn-dispatch-profile.test.sh and tests/mx-spawn-batch.test.sh.
  • tests/mx-daemon.test.sh, tests/mx-daemon-safety.test.sh, tests/mx-daemon-harness-model-resolution.test.sh and tests/mx-shared-maintainer-inheritance.test.sh: retain persistence/configuration facts under the new names.
  • Legacy delivery/scout/daemon fixtures normalize to common sessions with the correct output and persistence; malformed, duplicate and conflicting identities refuse safely.
  • A report task and implementation task differ in requested artifact, not whether the sub-agent can delegate. Existing local-only projects remain usable without inventing a remote.
  • Interrupt each intent/write/commit boundary, repeat the operation and assert a single accepted transition with preserved unfinished work.
  • Exercise replacement versus resume, old-attempt reports, changed briefs, wrong-recipient envelopes and native providers with no exportable child identity.
  • Test duplicate names, separate clones sharing a remote, linked worktrees, overlapping paths and three concurrent repo tasks; mutable display selection never alters recorded task routing.
  • A stale lease token cannot be accepted for a replacement allocation, and a same-named repository cannot be substituted.
  • Fixtures distinguish coordinator sessions from useful tasks, allow non-exclusive project domains and reject conflicting current owners or cyclic parentage.

Documentation and instruction updates

Update configuration schema, CLI help, examples and task lifecycle docs with a precise legacy-to-canonical mapping. Publish implemented fields and aliases with their schema version; distinguish accepted semantics from CLI syntax that is still unimplemented.

Definition of done

  • One common sub-agent representation supports lightweight roles; the main orchestrator remains dedicated to coordination.
  • Persistent sub-agents preserve current isolated-home behavior and pinned configuration.
  • Parent/task/session distinctions are explicit enough for nested routing and recovery.
  • Legacy readers have tests and no yolo value grants agent merge rights.
  • A1/A2 records and recovery primitives are implemented and versioned, with no database or competing state owner.
  • A9 project identity is implemented before discovery consumers, with task-local bindings and explicit borrowed-checkout ownership.
  • A stale lease token cannot be accepted for a replacement allocation, and a same-named repository cannot be substituted.
  • The assigned A11 foundation and focused interface checks pass; Phase 05 owns end-to-end coordinator integration, avoiding a circular dependency.
Integration risk

A global actor-to-subagent replacement cannot distinguish wire tokens, user labels, service daemons and agent roles. Change semantic owners first; leave historical bytes and compatibility aliases to the migration phase.
