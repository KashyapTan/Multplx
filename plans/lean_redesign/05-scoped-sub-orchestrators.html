Delegate a bounded project, repository or idea to a coordinator that manages its workers and reports reliably to the main orchestrator.

Overview

Multplx already has daemon homes, charters, handoffs and parent reply guards. Preserve those useful mechanisms as a scoped sub-orchestrator assignment in the common lifecycle. The root handles the human and cross-domain priorities while each coordinator decomposes its own work and delegates coding. Direct worker delegation remains available.

Implementation steps

  1. Add the public spawn path.Implement the A11 mx spawn <id> --sub-orchestrator form and its domain, scope, persistence, request identity and common harness options. Register and provision through existing owners; machine output reports canonical coordinator/domain/home/endpoint identity and partial failure truthfully.
  2. Bind the domain before launch.Resolve the parent/root and accepted scope revision, create a private home and concise charter, then launch at the recorded path. An idea may have no repository during research; implementation requires explicit project bindings. Duplicate requests recover the same operation.
  3. Keep common lifecycle semantics.Use the shared role model and preserve direct/nested delegation. Both coordinators delegate code/test changes. Standing domains idle between assigned tasks, and project overlap alone does not create exclusivity or a role approval.
  4. Resolve routes from durable identity.Generalize send/pending-reply dispatch beyond daemon tokens, bind generation and correlation, and replace caller-selected report paths with validated parent resolution. Keep lifecycle controls separate from conversational frames.
  5. Publish facts independently of model summaries.Compose a durable outbox with A3 at canonical outcome transitions and forward original event identities through each ancestor using receipts. The existing supervision path relays facts while a coordinator model is idle. Phase 06/08 integrate delivery/workflow producers; do not fake reasoning-only outcomes.
  6. Keep unanswered work visible.Separate transport acknowledgement from response and completion, retain missing replies and human questions, use bounded repair/escalation and route answers to the exact revision. Preserve original research and evidence pointers alongside summaries.
  7. Transfer assignments without competing owners.Use A1 receipts and A2 generations for scope updates and handoff. Reconcile old execution before granting mutable work to a new owner; preserve task IDs, historical outcomes and pending events without duplicating authoritative backlog records.
  8. Reconcile coordinator and child lifetimes.Restart from compact durable context and adopt still-running children. Parent outage queues returns while independent work continues. Make coordinator stop, subtree stop and home retirement distinct; retirement must transfer or settle child ownership and undelivered outcomes.
  9. Share resource admission.Compose Phase 04 capacity primitives across all descendant homes, count coordinator overhead, retain worker headroom, reconcile crashed reservations and prevent domain starvation. Do not hold shared locks during model turns or invent telemetry for opaque native children.
  10. Expose domain health and lineage.Publish scoped owner/child facts, pending outcomes, queue progress and observation age through the shared projection. The root does not drain foreign queues, and summary state cannot overwrite child task truth. Phase 10/11 implement the visual surfaces.
  11. Prepare compatibility and evidence.Provide mappings based on old charter responsibility for Phase 09, leaving ambiguous parent/scope records explicit. Keep existing supported local backend combinations; no remote transport, database, extra service or upstream code import.

Definition of done

  • The named spawn command creates or recovers a scoped sub-orchestrator through the common lifecycle without manual registry/home setup.
  • Researchers/implementers/reviewers can be delegated within the domain, while the main chat remains responsive and direct delegation remains available.
  • Recorded outcomes reach the root with correct identity even when an intermediate model omits its summary; missing responses and questions cannot silently disappear.
  • Task transfer, restart and retirement preserve one owner, active child continuity, durable messages and unfinished work.
  • Resource admission is shared across known descendants and leaves room for useful worker progress.
  • Core checks pass and later-phase integration APIs/fixtures are available; migration, delivery/workflow producers, visual work and combined performance claims remain assigned to their later owners.
Integration risk

An extra coordinator can reduce root context load but also add latency, hide facts behind summaries or exhaust capacity. Keep the hierarchy optional, publish facts mechanically and compare useful throughput under the same total resource budget.
