Lean Redesign 05 · Multplx

Review Tools Only When Requested

Retain deep-review and vplan as useful explicit tools and remove their hidden defaults, mandatory dependencies and approval coupling.

Phase 05 of 08Effort: MediumRisk: MediumPlanned · 2026-09-11
Implementation guide

Read porting.md for the shared product contract, skill disposition, migration boundaries and release acceptance. This phase is planned, not implemented.

Dependencies: 01, 02.

Overview

Deep-review is currently the registry fallback, and vplan is checked during routine bootstrap. Generic briefs, memory procedures and tracked workflows also bring those tools back into ordinary work. Opt-in must be true across all these entry points.

Behavior boundaries

DEFAULTAgent chooses suitable local checks; no tool pipeline is implied.
EXPLICIT REQUESTUser names a tool or knowingly selects its declared workflow stage.
ACTIVE RUNRecover requested runs and report their true results.
MISSING TOOLOnly the requested operation is unavailable.

Implementation steps

  1. Separate destination from review.Make ordinary PR publication the default for remote-backed changes. Retain local-only work. Do not interpret an old deep-review registry fallback or yolo flag as an explicit tool request for new work.
  2. Audit every implicit call site.Search root instructions, retained skills, generated templates, bootstrap, workflow examples, updater/memory prose and help strings. Remove the automatic use of deep-review or vplan, including when a plan or report happens to be HTML.
  3. Make readiness lazy.Run the tool self-check when it is invoked or when recovery handles its active recorded run. Missing vplan assets and unsupported deep-review harnesses must not block unrelated startup, delegation or delivery.
  4. Retain useful explicit behavior.Keep vplan loopback scope, comment persistence, artifact locks and identity cleanup. Keep deep-review findings, deadlines and real verification evidence when requested, but remove automatic push-approval handoff as the reason it exists.
  5. Remove automatic escalation from tool results.Allow routine corrections within the assignment. Persist a real user question when needed without requiring a special finding-decider role or a complete-none ceremony for every report.
  6. Specify legacy continuation.An in-flight old gate is preserved as evidence and can be resumed when its invocation was explicitly requested. Unknown legacy intent is surfaced for that run, not turned into a new global prerequisite.

Test plan

  • tests/mx-deep-review.test.sh, tests/mx-deep-review-lib.test.sh and tests/mx-deep-review-config-contract.test.sh: explicit invocation keeps meaningful validation behavior.
  • tests/mx-vplan.test.sh and crates/multplx-cli/tests/services_runtime.rs: retain loopback service, token, comment and identity guarantees.
  • tests/mx-bootstrap.test.sh and tests/mx-doctor.test.sh: ordinary work succeeds with optional assets missing; an active broken review is still visible.
  • Unregistered project, missing registry and Multplx self-repo task do not invoke a gate. An HTML plan request does not start a vplan server.
  • No requested pipeline is falsely labeled passed after a timeout or failed command; ordinary testing remains available without requesting either named tool.

Documentation and instruction updates

Update docs/vplan.md, docs/vplan-authoring.md, docs/delivery.md, configuration, bootstrap reference and optional-tool examples. Explain how explicit workflow selection establishes intent without creating a new global approval registry.

Definition of done

  • Neither review tool runs merely because a task changes code or asks for a plan.
  • Both tools remain usable when explicitly requested.
  • Ordinary work has no dependency on optional assets or gate state.
  • Requested runs retain truthful results and recoverable artifacts.
Integration risk

Deleting the tools would lose useful functionality the user explicitly wants available on request. Merely changing a default setting is also insufficient while generated workflow and brief text still invokes them.
