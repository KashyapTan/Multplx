Overview

The current engine already provides immutable snapshots, stage locks, output contracts and restart-safe state. Preserve that skeleton. Replace broker/actor executors and headless review coupling without allowing free delegation to skip the selected process.

Implementation steps

  1. Define execution placement.Replace broker/actor privilege terms with orchestrator-context and sub-agent-session choices. Discussion, research, synthesis and planning can use the orchestrator context; implementation stages must dispatch a sub-agent. Keep researcher/implementer/reviewer as descriptive roles. Preserve a selected fresh-session requirement and map legacy executor tokens through the versioned reader.
  2. Separate generic execution from review.Move reusable headless invocation and structured result transport to an appropriate existing shared owner. A normal agent stage must not instantiate deep-review policy, credential restrictions or a gate-agent identity.
  3. Allow internal delegation.A stage executor may start scoped children and reconcile their results. Its task remains active until the stage contract is met; work belonging to later stages cannot be silently pulled forward to bypass order.
  4. Preserve explicit interaction.Keep declared interactive/approve stages and their durable answer routing. Do not add approval points for routine engineering choices or every push. A false done report cannot satisfy output, command or local-commit evidence.
  5. Handle optional tools explicitly.New generic templates contain no implicit deep-review/vplan. A deliberately selected tool stage executes exactly as declared. Explain an old tool-bearing template before running it when user intent is unclear; never silently skip it.
  6. Simplify exceptional flow.Routine fixes and retries stay within the current stage. Do not auto-consume skip/reorder grants to finish faster. If the user changes the process, record a deliberate versioned plan change or new run with truthful cancellation/supersession, not a forged passed stage.
  7. Preserve restart behavior.Keep per-run serialization, command capture, immutable inputs, safe artifact paths and reconciliation. A child failure parks only dependent work and retains enough evidence to continue after correction. No workflow stage may merge a PR.
  8. Implement revision-bound human decisions.Record the question, task, accepted brief/workflow target and answer under A6. Batch non-urgent decisions, surface blockers and let unrelated work continue. A delayed answer cannot silently amend a different revision; do not infer preference from research or peer messages.
  9. Schedule dependencies and integration.Use the task dependency graph to identify runnable work, reject cycles and release dependents only on truthful current evidence. Preserve selected stage order. Assign shared-interface integration code to a sub-agent; avoid a blanket same-file concurrency ban.
  10. Preserve concise handoffs and current evidence.Pass original research and source pointers with the accepted brief to implementers, and accepted scope plus exact revision to reviewers. Keep a durable compact summary for human conversation and restart; compare implementation, checks, review and merge as separate facts.
  11. Implement multi-repo requests in one conversation.Decompose a human request into separately identified tasks using A9 project resolution and A3 correlation. Bind briefs, decisions, stages and evidence to each repo/checkout; ambiguous identity pauses only affected work. Preserve explicit cross-repo dependencies while independent workflows continue.
  12. Bind workflow stages to durable allocations.Record each delegated stage allocation and use Phase 03 recovery on resume. Preserve selected fresh-session requirements without confusing a session restart with permission to reset its worktree.
  13. Delegate workflow stages to scoped coordinators.Allow a stage to assign bounded domain orchestration using Phase 05 while retaining one stage owner, exact accepted revision, declared outputs and ordered advancement. Route human questions and cross-domain dependencies through A11.

Research, agreement and implementation

For an underspecified task, gather facts before implementation: dispatch research where useful, synthesize the original research artifact, discuss unresolved product choices with the human, and launch an implementer with an agreed brief revision. A known fix can go directly to implementation. This is task-dependent sequencing, not a compulsory research workflow for every request.

A selected planning workflow can contain iterative human discussion and requested vplan use. Store the accepted plan revision and bind implementation to it. Research cannot decide an unstated product preference, and a vplan comment is not automatically an accepted instruction change. Later user corrections update the task revision and steer only affected work while other tasks continue.

Require truthful outcome evidence from implementation, including relevant checks and known limits. The orchestrator can commission a reviewer or integration sub-agent when useful without invoking deep-review. Distinguish implementation completion, review readiness, passing current checks and human merge.

  • Missing artifact, false done, failed command, unanswered explicit interaction, duplicate resume, abort and changed snapshot remain rejected or waiting as appropriate.
  • Legacy explicit review workflow keeps its steps; generic new workflow performs direct agent delivery without gate approval; merge and auto-merge command stages remain outside agent authority.
  • Change the brief while research, implementation or a human answer is in flight; only current authorized evidence advances the affected task.
  • A dependency cycle is rejected; a blocked or unanswered task does not stall an independent one. An integration sub-agent handles coupled changes while the main orchestrator remains responsive.
  • Exercise known-fix direct delegation, underspecified research/agreement and explicit vplan discussion without a compulsory research or reviewer stage.
  • In one chat request feature A in repo 1, feature B in repo 2 and feature C in repo 3; steer one task and change TUI context while checking that the other workflows, questions and outcomes remain correctly bound.
  • A workflow resumes an interrupted stage at the recorded allocation and cannot reuse a different task's path.
  • Research-to-implementation with nested children completes only after required stage outputs; sub-orchestrator readiness or a summary alone cannot advance the stage.

Definition of done

  • Every selected stage remains binding, including deliberately chosen user-interaction stages.
  • Agent stages freely delegate; implementation stages never execute project coding in the main orchestrator context.
  • Ordinary workflows do not depend on deep-review internals or credentialed delivery.
  • Resumes, retries and legacy snapshots preserve truthful stage evidence.
  • A5/A6 dependency, decision and artifact handoffs work across restart with current evidence and no main-agent coding.
  • One main conversation handles concurrent multi-repo plans and implementation with optional scoped sub-orchestrators and no context leakage.
  • A workflow resumes an interrupted stage at the recorded allocation and cannot reuse a different task's path.
  • The assigned A11 integration and its focused check above pass with Phase 05.
Integration risk

The existing command approve gate executes the command before requesting approval. Do not use an after-the-fact gate as a merge guard or as consent to run an undisclosed optional tool; establish tool selection before execution and keep agent PR merges forbidden.
