Implementation steps

  1. Finish the vocabulary sweep.Update public prose, CLI help, generated strings, UI labels, runtime symbols where practical and canonical filenames. Old role tokens may remain only as documented compatibility readers/fixtures or historical records. Distinguish service daemons from agent roles.
  2. Audit policy through the whole system.Search for blocked push URLs, removed skill names, mandatory deep-review, vplan auto-use, role-specific delegation refusal and yolo merge authority. Map each remaining hit to history, compatibility or a defect to fix.
  3. Update tests by guarantee.Replace tests whose purpose was the deleted restrictions. Preserve relevant lock, queue, schema, poll, cleanup and workflow assertions and update the runner inventory rather than silently dropping suites. Run the full Rust and behavior checks listed in porting.md.
  4. Verify real integration boundaries.Use isolated homes and namespaces for supported tmux/Herdr/cmux paths and changed Claude/Codex/Cursor/Pi surfaces. Prove native tool availability, publication credentials, watcher recovery and explicit review invocation. Record an unavailable integration honestly and do not widen unsupported backend combinations by renaming them.
  5. Validate the release package before restoring discovery.Create an isolated release fixture containing the lean contract under AGENTS.md and verify startup exactly once. Keep the development checkout on AGENTS_E.md throughout implementation and checks. Root-contract discovery must not learn the temporary filename.
  6. Perform deliberate final cutover.Only at the release step, rename the completed lean AGENTS_E.md to AGENTS.md, update its current links and inventory, and rerun instruction/launcher/documentation checks against the restored tree. Use a fresh session for operational startup. If the user elects to keep the development checkout dormant, deliver the tested package and clearly mark repository cutover pending.
  7. Publish evidence and stop at the PR.Provide concise changed behavior, relevant test results, migration guidance and a reviewable PR. The human performs the merge. Update this roadmap status only after actual acceptance; do not call planned features implemented.
  8. Run the agreed concurrency comparison.Execute the A8 1/5/10/20-task workload matrix across independent projects and coupled changes. Record actual active sessions, correctness, throughput, resource use and human attention separately; native observation gaps and unavailable measurements stay explicit.
  9. Close reliability and visual acceptance together.Run the A1-A3 interruption/retry/stale-attempt matrix with A4 slow-provider and A5 capacity/dependency scenarios. Verify A6 current evidence and human decisions in the packaged A7 dashboard. No required mechanism or failed performance target may be relabeled optional to close the release.
  10. Publish reproducible evidence.Record code revision, machine, backend/harness versions, workload, sample counts, commands, results and unresolved limitations at the verification owner. Compare results to the small-concurrency baseline before claiming velocity gains. Keep human merges human-executed.
  11. Verify the complete installed multi-repo experience.After a package-only installation, run scenarios 19-39 from arbitrary caller directories, including an example non-repository dev root. Use one chat for three repositories at different depths, exercise discovery config, concurrent launch/retry, context changes, restart and TUI navigation. Verify borrowed checkout preservation and actual provider connection limits.
  12. Verify complete Treehouse retirement.Run A10 failure/retention/migration scenarios and the no-Treehouse installation matrix. Audit binary dispatch, hooks, adapters, probes, instructions, CI and tests; old names remain only in documented migration/history. Record cold and safe-reuse worktree setup costs without claiming parity before measurement.
  13. Verify hierarchical coordination end to end.Run A11 scenarios 32-39 and compare direct versus domain-delegated 1/5/10/20-task trials under equal total budgets. Verify silent-model outcome relay, bounded missing-reply recovery, shared capacity, task transfer and packaged TUI/Viz views.
