Lean Redesign 04 · Multplx

Agent Delivery, Human PR Merges

Let agents commit, push and open PRs directly, while retaining the single explicit product permission boundary at PR merging.

Phase 04 of 08Effort: HighRisk: HighPlanned · 2026-09-11
Implementation guide

Read porting.md for the shared product contract, skill disposition, migration boundaries and release acceptance. This phase is planned, not implemented.

Overview

Agent launch currently strips credentials and makes origin non-writable. The delivery implementation then refuses agent sessions and requires approved local handoffs. These are intentional removals; the useful identity, retry and PR-monitoring mechanisms should survive.

Behavior boundaries

LOCAL WORKAgent commits and reports its actual verification.
PUBLISHPush branch; create or update PR; register canonical URL.
HUMAN MERGENo agent merge, auto-merge, merge queue or target-branch bypass.
RECONCILERead merge state; preserve unlanded work until cleanup is justified.

Implementation steps

  1. Decouple delivery from approval.Make the normal agent path independent of ready-to-push approval, review gate state, waivers and separate scheduler credentials. Keep an optional idempotent convenience command; ordinary Git/forge commands remain usable.
  2. Restore normal authentication.Remove the origin push overlay, empty credential helper and blanket GH/SSH suppression from ordinary worker launch. Preserve user-configured authentication precedence, bounded commands and secret-free state. Review headless workflow/review helpers separately.
  3. Make publication repeat-safe.Record branch/base/commit and canonical PR identity as facts. Reconcile push success followed by PR-create failure, PR-created-before-record failure and subsequent branch revisions. Never create duplicate PRs on a retry or claim an unrun review passed.
  4. Keep the PR record path.Register directly opened PRs through the existing canonical PR owner so read-only polls and snapshots continue working. Preserve the private static poll trust, queue-before-retirement order and identity-bound cleanup.
  5. Enforce the product merge boundary.Keep agent merge refusal in owned commands and add narrowly scoped supported harness checks for ordinary merge actions. Remove yolo, merge-red and workflow/automation bypass paths. Do not block general git merge/rebase operations inside task worktrees. See porting.md for the honest limitation of command-level enforcement.
  6. Update cleanup and operator usage.Open PRs remain unlanded and their work remains recoverable. Human merges are observed normally. Existing service receipts stay readable for migration, and a pending legacy receipt never becomes a new authorized push merely because the software was upgraded.

Test plan

  • tests/mx-push-service.test.sh and tests/mx-pr-merge.test.sh: agent publication succeeds without approval; agent PR merging stays refused; human helper records truthful state.
  • crates/multplx-cli/tests/review_runtime.rs and tests/mx-deep-review.test.sh: review evidence is optional and cannot manufacture approval or merge authority.
  • All tests/mx-pr-check-security-*.test.sh scenarios remain for inert parsing, identity, quarantine and retirement; revise only obsolete publication-policy assumptions.
  • tests/mx-teardown.test.sh: pushed/open-PR/dirty work is not silently recycled.
  • Fake-forge scenarios cover partial failure and retries; a dedicated live test repository proves the supported authentication and human-merge boundary without merging a PR from an agent session.

Documentation and instruction updates

Rewrite docs/delivery.md around ordinary branch publication and human merging. Update README examples, generated briefs, credentials documentation and verification records; remove instructions requiring users to run delivery from another shell.

Definition of done

  • An orchestrator and sub-agent can publish an authorized branch and open/update its PR without extra Multplx approval.
  • No supported agent path grants PR merge or auto-merge rights.
  • PR identity, actual validation results, restart receipts and polling remain correct.
  • The documentation does not claim a command hook is a security boundary against arbitrary code with broad credentials.
Integration risk

Credential access is being deliberately expanded for publication. The implementation must not imply that removing the agent-session check from deliver also authorizes removing it from pr-merge, or that a broadly privileged token intrinsically prevents remote merges.
