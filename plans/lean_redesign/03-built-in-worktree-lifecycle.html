Built-in Git Worktree Lifecycle

Replace Treehouse with a small internal Git lifecycle that returns exact paths and preserves owned work.

Phase 03 of 12Effort: HighRisk: HighPlanned · 2026-09-14
Implementation guide

A10 in porting.md owns the worktree contract. The research record maps upstream behavior to actual Multplx callers. Implementation is in progress; required validation remains open. See the implementation evidence below.

Dependencies: 02. Implement allocation receipts using A1 primitives here; Phase 04 composes them with durable delegation/inbox actions, avoiding a circular dependency. Phase 09 performs legacy-home transfers.

Overview

Ordinary spawn currently types treehouse get into a backend terminal and polls its directory before publishing metadata. Home seeding separately requests a durable lease, and teardown invokes destructive return after its own safety checks. Replace those external operations with one typed resource owner inside Multplx, without duplicating the whole Treehouse application.

Behavior boundaries

ACQUIREExact project/base, isolated path and durable allocation identity.
LAUNCHAgent starts at the returned path; no terminal cwd guessing.
RETAINUnfinished or uncertain work survives endpoint loss.
RELEASEExact-generation cleanup of proven owned resources.

Implementation steps

  1. Implement the small resource owner.Add acquire, inspect/list, release/retain and explicit scoped prune through the existing domain/CLI architecture. Use task/project/common-Git identity, exact base and per-acquisition tokens from Phase 02. Reuse only verified idle disposed worktrees; prefer a fresh path when cache/content safety is unknown.
  2. Make acquisition transactional.Reserve the path/operation before Git mutation, create the isolated worktree at the recorded commit, validate top-level/common-directory identity and atomically publish allocation facts. Repeated requests reconcile rather than allocate twice. Test Git success before receipt publication and incomplete-directory recovery.
  3. Launch from the returned path.Replace every literal Treehouse invocation and sixty-second cwd polling branch with typed acquisition before endpoint creation. Pass the exact path to tmux/Herdr/cmux within their supported matrix, bind endpoint and task metadata to that allocation and preserve useful isolation checks.
  4. Unify durable reservation semantics.Ordinary task allocations and persistent Git-backed homes retain ownership without live processes. A packaged non-Git runtime uses a private persistent-home directory provisioned by home seed, while its project tasks still use Git worktrees. Do not invent a clone of the application merely to provision a home.
  5. Implement guarded disposition.Keep existing truthful dirty/unlanded/PR checks and exact-generation release under A10. Stop only verified task-owned processes, retain unknown occupants and unfinished files, and use Git-supported removal of exact owned paths. Shell exit never performs automatic destructive return.
  6. Keep reuse and prune narrow.Retain safe reusable caches without promising Treehouse's whole warm-pool/hook behavior. Unclassified ignored content stays retained. Prune only explicit owned safe candidates with preview and a recheck; do not sweep foreign worktrees or delete caller-owned checkouts.
  7. Expose canonical recovery and inventory.Provide typed allocation observations to doctor, snapshots and later TUI/Viz phases. Corrupt records or unexplained on-disk worktrees remain unknown/retained until reconciled. Maintain bounded operation reservations and lock ordering without holding a home-wide lock through external Git work.
  8. Prepare migration readers.Read versioned v2.0.1-style metadata and known later fields inertly without executing Treehouse. Specify the ownership checks and relocation receipts consumed by Phase 09. Old wrapper shells must be quiesced before any resource transfer; unknown versions or foreign entries cannot be silently adopted.
  9. Remove the dependency end to end.Retire installer implementation/dispatch/adapters, version pins, probes, bootstrap messages, shell assumptions and CI installation. Update command inventory, generated briefs, operational skill mechanics and dependency documentation; do not add a global fake treehouse binary or silently install the old tool on failure.
  10. Provision coordinator homes without project copies.Expose the A10 private-directory home and worker allocation results to Phase 05. Coordinate allocations by canonical project/common-Git identity across homes; no coordinator launch requires a Treehouse lease or cloned runtime.

Test plan

  • Add focused Rust domain tests for real temporary Git repositories/worktrees, allocation concurrency, exact-base selection, shared-Git identity, local-only repos, branch collision, retried requests and corrupt records.
  • Exercise acquire-before-record, Git mutation interruption, endpoint failure, home-seed rollback, release-before-record and stale token after path reuse. No failure may double-assign a resource or delete unfinished work.
  • Extend tests/mx-teardown.test.sh, tests/mx-daemon-safety.test.sh, tests/mx-daemon.test.sh and tests/mx-spawn-dispatch-profile.test.sh with internal allocation fixtures and real Git effects; remove reliance on a fake Treehouse that always succeeds.
  • Retain and adapt stale Git lock, squash-merge, unpushed/open-PR, dirty/untracked/ignored-file, persistent zero-process lease and unsafe-path coverage; unknown liveness retains resources.
  • Update tests/mx-bootstrap.test.sh, tests/mx-doctor.test.sh, tests/mx-bin-runtime-inventory.test.sh and Rust dispatch/probe tests so Treehouse absence succeeds and obsolete installer commands cannot download it.
  • Supported tmux/Herdr/cmux launch checks verify the exact returned worktree and no shell-driven acquire/cwd polling. Do not widen unsupported persistent-home combinations.
  • Test explicit scoped prune against unrelated worktrees, caller-owned checkouts, foreign pools, missing repositories and corrupt allocation records.
  • Run with Treehouse absent and a sentinel executable that fails if invoked. Disable downloads in integration fixtures; normal lifecycle must use only Git and existing declared tools.
  • Record acquisition, setup and release latency plus disk/cache behavior for fresh and safely reusable worktrees in A8 trials; distinguish measured cost from expected velocity benefits.
  • Two domain homes allocate isolated worker worktrees from one borrowed project without duplicate ownership or changes to the user checkout.

Documentation and instruction updates

Publish implemented worktree command help and record/schema ownership, update dependency/setup and lifecycle docs, remove Treehouse skill triggers/install guidance, and retain upstream research only as rationale and migration history. Exact public syntax is finalized with the CLI; runtime compatibility is defined by A10 outcomes, not every upstream flag.

Definition of done

  • No supported new runtime path installs or invokes Treehouse; the built-in manager serves task allocation, persistent reservations, inspection and safe cleanup.
  • Exact path/base/allocation identity reaches every supported session launch, with restart-safe ownership and no cwd-guessing loop.
  • All required interruption, race, retention, borrowed-checkout and no-dependency tests pass.
  • Migration readers and handoff receipts are ready for Phase 09 without taking over unrelated pools or relying on an external executable.
  • The implementation remains a small Git resource lifecycle without a separate database, daemon, general hook engine or complete Treehouse clone.
  • The assigned A11 foundation and focused interface checks pass; Phase 05 owns end-to-end coordinator integration, avoiding a circular dependency.
Integration risk

Removing the executable before replacing all allocation and teardown callers breaks ordinary workers and persistent homes. A path-only release or automatic shell-exit reset would also defeat the new attempt-generation and unfinished-work guarantees.
