Overview

The current delegation guard denies tools by name shape, while in-flight supervision depends on metadata that only Multplx spawn creates. Freedom requires removing that guard and making native session limits visible without turning registration into another permission gate.

Implementation steps

  1. Remove actual delegation fences.Remove the shape-based guard and tracked Cursor prohibitions. Audit generated launch settings and documented local deny lists. A no-op compatibility entry may serve old hooks for a defined transition period; no escape environment variable should be needed.
  2. Keep nested CLI mutation correctly scoped.Use the initiating task and parent identity for child launch and return routing. Reuse lock owners and atomic writers; never start a competing primary session in the parent home to append a report or create a child.
  3. Observe native children where supported.Use native lifecycle events or tool results to bind provider/session IDs to the existing task/session model. Report start, result and interruption through the same state owner. Never scrape arbitrary prose into authoritative completion facts.
  4. Handle unsupported observation honestly.Allow the native tool. Record session-bound delegation on the parent task with the available evidence and explain its recovery limitation. Do not invent a full backend, duplicate dashboard ledger, or native-resume guarantee.
  5. Preserve agent-to-agent communication.Route peers through validated recipient/home identity and task-scoped records; preserve correlation on retry. Internal messages carry task context and do not grant merge authority. Keep long results in artifacts with status pointers.
  6. Reconcile continuity.Retain singleton watcher locks, queue-before-notification ordering, canonical status reconciliation and AFK ownership transfer. Reconcile live independent children after parent restart; classify unavailable native work as interrupted, preserving artifacts for continuation.
  7. Implement durable inbox handling.Replace print-and-delete completion with A3 claim, durable disposition and acknowledgement through the existing queue/CLI owner. Recover abandoned claims after owner reconciliation; a waiting disposition retains its continuation trigger. Keep critical transitions and coalesce only replaceable progress.
  8. Make action retries converge.Use A1 operation receipts and stable request IDs to reconcile an existing child before replaying uncertain spawn requests. Reuse pending-reply correlation and validate A2 attempt/revision identity before accepting reports. Publication consumes the same mechanism in Phase 06.
  9. Isolate slow supervision checks.Move serial due checks and forge probes into bounded work with individual deadlines and partial results while keeping wake ingestion responsive. Do not hold shared locks across external calls; preserve singleton ownership and evidence precedence.
  10. Extend capacity-aware deferred work.Use the existing headroom owner for configured resource limits, durable queued intent, priority changes and starvation prevention under A5. Resume runnable entries after restart without duplicate launches. Declare opaque native-child limits and keep native delegation usable.
  11. Support additional terminal clients.Expose the existing owner/endpoint and durable inbox APIs needed by Phase 11 without relaxing the home lock. Correlate one multi-repo request with stable per-task operations so partial acceptance and retried submission converge. Preserve selected repository context in deferred work.
  12. Use the internal allocation result.Consume Phase 03 acquire/release receipts when launching scoped children. Keep A3 inbox idempotence and capacity scheduling aligned with resource reservations; do not recreate Treehouse shell injection or cwd polling.
  13. Expose parent-channel and shared admission primitives.Provide A3 inbox/outbox receipts, validated destination resolution, critical event publication hooks and A5 root-scoped admission primitives for Phase 05. Keep message delivery, response and completion separate and avoid a second messaging service.

Required reliability improvements

Implement A2-A5 using the existing state owners: attempt-bound messaging, durable claim/disposition/acknowledgement, repeat-safe actions, bounded watcher checks and capacity-aware deferred work. The assessment explains the observed gaps; these are accepted requirements, not implemented guarantees.

  • Test a crash after a wake is printed but before its dependent action is recorded; the task must remain recoverable without relying on chat history.
  • Test duplicate request delivery and an old implementer reporting done after replacement; neither should create duplicate work or advance the new attempt.
  • Preserve prompt/plan revision, recipient identity, correlation and artifact references across the researcher-to-orchestrator-to-implementer handoff.
  • Allow narrow peer questions, but route accepted scope, completion and user decisions through the owning task so the orchestrator remains informed.

Test plan

  • tests/mx-subagent-pretool-check.test.sh and tests/mx-cursor-adapter.test.sh: replace denial expectations with allowed native delegation and unaffected supervision checks.
  • tests/mx-report.test.sh, tests/mx-report-mcp.test.sh, tests/mx-operational-input.test.sh, tests/mx-pending-reply.test.sh and tests/mx-send-strict.test.sh: same task binding and reply semantics.
  • tests/mx-wake-queue.test.sh, tests/mx-watcher-lock.test.sh, tests/mx-watch-triage.test.sh and tests/mx-signal-precedence.test.sh: preserve durable ordering and classifier evidence precedence.
  • Native child completes, parent restarts, child has no resumable identity, duplicate reply arrives, wrong-home report attempts append, and a persistent sub-agent creates a grandchild.
  • Exercise actual supported Claude/Codex/Cursor/Pi native tool surfaces in isolated sessions. Missing provider hooks are a declared observation limit, not grounds for a delegation ban.
  • Crash after display, after claim, after action creation and before acknowledgement; restart and recover one disposition without duplicate launches. Re-deliver identical requests and retain waiting continuations.
  • Run a slow check beside healthy reports and verify bounded progress; saturate capacity, restart the queue, change priorities and demonstrate small-task progress without a delegation permission prompt.
  • Race client submissions and repeat a partially accepted three-repo request; one owner handles it, accepted items do not duplicate and an unresolved item does not block independent tasks.
  • Duplicate dispatch and failed endpoint startup preserve a single owned worktree or a recorded retained allocation.
  • Delayed and duplicated events cross home boundaries with stable identity; a slow child cannot block unrelated ingestion and a parent never consumes a foreign queue.

  • Canonical state accounts for supported native observations and declares unsupported recovery honestly.
  • Locks, wakes, status binding, AFK and correlated replies retain their meaningful guarantees.
  • Durable handling, attempt-bound reports, correlated replies and recoverable action receipts pass failure injection.
  • A stalled check does not block healthy wake ingestion, and capacity queues retain accepted work without starvation or duplicate ownership.
  • External terminal requests preserve project binding and converge through one orchestrator inbox without a second writer.
  • Duplicate dispatch and failed endpoint startup preserve a single owned worktree or a recorded retained allocation.
  • The assigned A11 foundation and focused interface checks pass; Phase 05 owns end-to-end coordinator integration, avoiding a circular dependency.
Integration risk

Do not recreate the old guard as a mandatory tracking wrapper. Also do not call unobserved native children durable: preserving user freedom and reporting actual provider limits are both part of acceptance.
