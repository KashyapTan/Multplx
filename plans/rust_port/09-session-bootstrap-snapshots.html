Startup order

1. acquire and verify the per-home session lock
2. run detect-only bootstrap checks
3. if locked, run authorized bootstrap mutations
4. if locked, drain the durable wake queue
5. render one harness supervision block
6. render context owners exactly once
7. render bounded system-state digest
8. print the next-step reminder
Ordering is behavior

A Rust rewrite may not parallelize, cache, or reorder startup sections if doing so could perform mutation before lock proof, hide a wake, read state twice, or render a projection from mixed-time inputs.

Implementation steps

  1. Port snapshot models first.Build one typed read-only model for tasks, endpoints, daemons, backlog identity, queues, holds, runs, and artifacts.
  2. Port deterministic renderers.Preserve JSON, TOON, compact text, human view, timeline ordering, bounds, labels, and unavailable-state representation.
  3. Port doctor as read-only composition.Reuse authoritative probes and lifecycle predicates rather than copying proof rules into a new check layer.
  4. Port proof-bound fixes separately.Keep stale watcher-lock cleanup and orphan wake-row prune behind the same evidence and lock requirements.
  5. Port bootstrap detection.Preserve silent success, exact actionable classes, tool version checks, backend and headroom validation, and no install without current-session consent.
  6. Port bootstrap mutations.Run only under verified session-lock ownership and preserve non-executing migration, system sync, daemon sync, and liveness recovery.
  7. Port supervision rendering and nudge.Keep harness selection, primary scope, existing lock behavior, and exact one-line transport.
  8. Port session-start composition.Render each section once from bounded reads, leave the queue untouched in lock-refused mode, and preserve diagnostic prominence.
  9. Cut over startup last.Run repeated real startups with empty, active, corrupt, lock-refused, AFK, stale, daemon, and queued-wake homes.
