Multplx · Rust Port Roadmap

Port the runtime in thirteen safe portions

A dependency-ordered implementation roadmap that keeps Multplx runnable, preserves every safety contract, and proves each Rust slice against the existing behavior suite before the next slice begins.

13 portions Program effort: Very High Peak risk: High Source owner: PORTING.md

Execution rule

No big-bang rewrite

Only one numbered portion may change its default implementation at a time. Every portion must leave the repository runnable, retain the black-box compatibility suite, and satisfy its own deletion gate before legacy code is removed.

Authoritative cross-cutting contract

PORTING.md owns the rules shared by every portion: exact behavior parity, dual-engine testing, data compatibility, security review, documentation review, CI progression, and final legacy deletion. These artifacts divide the work without restating or weakening that contract.

Program-wide gates

GateRequired proof
Source ownershipEvery active bin/* file belongs to exactly one portion, and the final inventory check reports no missing or duplicate assignments.
Behavior parityThe same black-box assertions pass against isolated legacy and Rust homes, with differences limited to explicitly normalized unstable values.
Data safetyExisting operational homes require no migration, and every writer preserves record bytes, permissions, atomicity, and recovery behavior.
CompatibilityLinux, macOS, tmux, Herdr, cmux, and every claimed harness are checked at the portion that owns their integration surface.
DocumentationCurrent owners, skills, hooks, workflows, CI, and verification evidence change in the same portion as their implementation.
DeletionLegacy business logic is removed only in Portion 13 after all prior portions have passed their Rust-default rollback windows.
