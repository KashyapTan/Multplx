Final installation model

verified release artifact or explicit local Cargo build
  └─ installed multicall Rust binary
       ├─ stable global multplx entry
       ├─ compatibility command names via links or exec-only adapters
       ├─ registered code root and operational home
       └─ interactive Bash or Zsh activation adapters

retained shell
  ├─ interactive shell initialization only
  └─ minimal exec transport where a host requires a script path

forbidden retained shell
  ├─ domain parsing
  ├─ policy decisions
  ├─ locking or durable state mutation
  └─ orchestration or lifecycle logic

Implementation steps

  1. Port launcher validation.Preserve literal path files, executable discovery, shim recursion prevention, root and home validation, backend environment, nested activation, and child-only cwd changes.
  2. Port install, update, and uninstall.Support verified prebuilt artifacts or an explicit local build, checksums, modes, atomic path records, existing-checkout and managed layouts, rollback before mutation, and safe removal.
  3. Retain minimal shell activation adapters.Keep Bash and Zsh rc behavior, user configuration sourcing, prompt marker, real harness capture, and exec-only shims without moving policy back into shell.
  4. Port the behavior-test scheduler.Reproduce exact inventory coverage, family mapping, resource manifest, conflict rules, LPT shards, changed-file selection, timing markers, JSON artifacts, aggregation, and exit behavior.
  5. Port the isolation proof.Derive the same conflict matrix, repeat candidate combinations, detect leaked files and processes, and emit equivalent JSON evidence.
  6. Port the documentation checker.Preserve scope, exclusions, exact-one classification, required pointers, setup routing, local links, and bounded errors.
  7. Update CI to Rust-native entry points.Build release binaries once, run Rust tests, run every black-box lane against Rust, retain real Herdr and live-harness gates, and update measured shard evidence.
  8. Update every instruction surface.Review README, contributor guidance, architecture, operator docs, verification records, AGENTS.md, all skills, hooks, Pi extensions, workflows, shell adapters, examples, and deep-review configuration.
  9. Run the repository-wide reference sweep.Find every old path, sourced function, interpreter dependency, environment seam, hook command, workflow command, fixture assumption, and docs link.
  10. Remove legacy business logic.Keep only documented host adapters, test that they contain no policy or state mutation, remove unused Bash, Node, and Python runtime requirements, and retain rollback through release installation rather than mixed engines.
  11. Publish final performance and compatibility evidence.Compare release startup, session start, snapshots, watcher resources, queue latency, workflow, services, and full-suite wall time against Portion 01.

  • Every path returned by git ls-files 'tests/*.test.sh' through the Rust test scheduler with exact coverage proof.
  • Portable parallel, portable serial, required Herdr, macOS, and live harness verification.
  • Repeated isolation proof and leak-free scheduler evidence.
  • Fresh install, existing-checkout install, managed install, upgrade, rollback before mutation, uninstall, and broken-download recovery on Linux and macOS.
  • Documentation audience, link, naming, instruction-owner, hook, workflow, and compatibility checks.
  • Repository search proving no removed interpreter or script path remains active.
  • Release performance comparison with raw and summarized evidence.

Definition of done

  • All active runtime files are Rust or documented minimal host adapters.
  • No retained shell adapter parses domain records, decides policy, locks state, or orchestrates lifecycle.
  • The complete root behavior inventory passes against Rust only.
  • Existing operational homes work without migration.
  • All supported backends and harnesses are empirically re-verified.
  • Agents remain credential-free and destructive boundaries remain fail closed.
  • Operator, maintainer, agent, hook, workflow, CI, and verification surfaces describe the Rust implementation accurately.
  • Removed Bash, Node, and Python runtime dependencies no longer appear in bootstrap or installation requirements.
  • The measured release meets the accepted robustness and performance targets.
