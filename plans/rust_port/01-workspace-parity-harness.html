Overview

This portion creates the engineering foundation for every later port without replacing a production behavior path.

The existing shell implementation remains the normal runtime while Rust gains a build, test, packaging, and black-box comparison surface.

Safe stopping point

At the end of this portion, the repository builds and tests Rust code, but every operator command still uses the existing implementation. Reverting the new workspace removes the experiment without touching operational state.

Target test architecture

existing tests/*.test.sh
  └─ tests/lib.sh implementation adapter
       ├─ legacy command in isolated home
       └─ Rust release command in isolated home
            └─ compare:
                 exit status
                 stdout and stderr
                 filesystem paths and bytes
                 file modes
                 surviving child processes

Normalization may cover only unstable roots, PIDs, ports, timestamps, and random tokens.

Ordering, wording, permissions, missing fields, and extra processes are never normalized away.

Implementation steps

  1. Freeze the current inventory and baseline.Record git ls-files 'bin/*', git ls-files 'tests/*.test.sh', the full behavior-suite result, current CI lane composition, and release-relevant command timing.
  2. Create the workspace and crate boundaries.Keep dependencies centralized, commit the lockfile, deny warnings in CI, and leave crate APIs intentionally small until real ports exercise them.
  3. Create the multicall skeleton.Support explicit subcommand dispatch and argv[0] compatibility, but expose only a diagnostic no-op until a command is actually ported.
  4. Add deterministic test support.Provide isolated homes, fake PATH entries, clocks, process identities, permission inspection, bounded process cleanup, and structured filesystem manifests.
  5. Add the implementation selector.Make selection explicit and test-only. Never silently fall back after a Rust command has started a mutation.
  6. Add CI without changing current proof.Run formatting, clippy, unit tests, release build, and Linux/macOS compilation in addition to every current black-box job.
  7. Document the contributor workflow.Update contributor commands and architecture pointers without claiming any runtime command has moved.

Test plan

  • cargo fmt --check, clippy with warnings denied, workspace tests, and a release build.
  • A multicall dispatch test covering explicit subcommands, argv[0], help, unknown commands, and exit code 2 for usage failures.
  • A differential harness self-test proving it detects stdout, stderr, status, mode, content, ordering, and process leaks.
  • The complete existing behavior suite against the unchanged legacy default.
  • Linux and macOS release compilation.
  • A baseline timing artifact that records command, machine, build mode, iterations, and raw results.

Definition of done

  • The workspace builds in release mode on Linux and macOS.
  • The Rust test-support layer can prove intentionally injected differences.
  • All existing behavior tests still pass against the legacy default.
  • No operational file, hook, skill, workflow, or launcher selects Rust implicitly.
  • Portion 02 can add real core modules without redesigning the test runway.
