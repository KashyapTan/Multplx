Rust Port 10 · Multplx

Decisions, Overrides, and Workflows

Port maintainer authority mechanics and the workflow engine as explicit Rust state machines, preserving single-use decisions, exact policy bindings, immutable run snapshots, stage order, and restart-safe reconciliation.

Portion 10 of 13 Effort: Very High Risk: High Incremental Rust migration

Overview

This portion owns the durable mechanics that pause work for a maintainer decision, authorize one exact policy exception, and execute a declared multi-stage workflow.

These are authority mechanisms rather than ordinary CRUD, so Rust types must make invalid transitions hard to represent and every mutation auditable.

No authority expansion

The Rust port may enforce an accepted decision more deterministically, but it may not broaden yolo posture, infer approval, create reusable exceptions, skip workflow stages, or turn a factual failure into a policy override.

State-machine boundaries

DECISION HOLDopen → answered → consumed, with one correlation key and durable backlog visibility.
OVERRIDErequested → decided → bound → consumed → recorded, never reusable.
WORKFLOW RUNcreated → stage execution or gate → completed, failed, aborted, or waiting.
STAGEpending → running → passed, failed, waiting, or approved skip under exact authority.

Implementation steps

  1. Freeze all transition tables and record formats.Capture accepted states, actor roles, binding fields, lock behavior, output, journal events, backlog interactions, and recovery paths.
  2. Port decision holds.Validate task and key identity, create one durable hold, attach it to backlog state, record the direct answer, consume once, and preserve unresolved completion gates.
  3. Port override records.Model request, decision, exact subsystem binding, consumption, and audit as typed records with atomic single-use transitions.
  4. Port canonical binding generation.Keep each registered subsystem's accepted actions and factual limits explicit and reject unknown or extra fields.
  5. Port exact command overrides.Hash or otherwise bind the exact command and context, consume before execution, run only the approved syntax contract, and record the truthful result without pretending validation passed.
  6. Port the workflow definition parser.Preserve the constrained frontmatter grammar, stage schema, tracked-definition rule, substitution, output paths, contracts, and validation errors.
  7. Port immutable run creation.Snapshot the definition once, hash it, create private stage and prompt records, register backlog state, and never reread the tracked definition during resume.
  8. Port stage executors and reconciliation.Keep broker agent, actor agent, command, gate, contract, approval, skip, reorder, abort, and journal behavior in exact order.
  9. Cut over decisions and workflows together.Prove a restart at every state boundary and preserve compatibility with legacy deep-review and delivery adapters until Portion 11.

Definition of done

  • All seven owned files run through Rust by default.
  • Decisions and exceptions are exact, single-use, identity-bound, and auditable.
  • Workflow snapshots remain immutable and restart-safe.
  • Stage order, gates, contracts, skips, and reorders cannot occur without their current authority.
  • Portion 11 can consume typed authority records without expanding them.
