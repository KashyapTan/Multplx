Rust Port 04 · Multplx

Backend Facade and tmux

Define the Rust runtime-backend contract and prove it first against the tmux reference backend, while Herdr and cmux remain on explicit compatibility paths until their own portions pass.

Portion 4 of 13 Effort: High Risk: High Incremental Rust migration

Overview

This portion turns the backend abstraction into a typed Rust interface and ports only the reference tmux implementation.

The Rust facade remains shadow-only for production dispatch until Portions 05 and 06 complete every supported backend.

Partial backend cutover is forbidden

A task may not silently switch between Rust and shell inside one backend operation. Selection happens once before mutation, and the selected implementation owns the entire operation.

The real Rust trait must use typed targets, results, timeouts, and error classes rather than the illustrative signatures above.

Unsupported operations are explicit capabilities, not empty success values.

Implementation steps

  1. Capture the facade matrix.Record every current operation, accepted backend, argument order, stdout shape, status code, and unsupported case.
  2. Define typed target identities.Keep backend name, container or session, endpoint identifiers, and expected label together so a caller cannot mix identities.
  3. Implement command execution.Use argument arrays, bounded capture, explicit environment, stable locale where required, and structured diagnostic context.
  4. Port tmux container and task lifecycle.Preserve session existence checks, window naming, working directory proof, target readiness, and creation output.
  5. Port tmux composer and submit behavior.Reuse the Rust composer rules from Portion 02 and preserve literal send, Enter retry, settle, busy detection, and acknowledgement semantics.
  6. Port liveness and current-state reads.Distinguish unreachable, idle, working, blocked, done, and unknown without promoting heuristic output to authority.
  7. Port actor reconciliation and peek.Keep the current precedence and bounded-output contract.
  8. Run shadow tests only.Do not make the Rust facade the general production default until Herdr and cmux implementations pass.

Test plan

  • Fake tmux tests for every command construction and parser branch.
  • Real tmux smoke tests for create, readiness, literal send, submit, capture, path, liveness, and verified kill.
  • Composer ghost, pending input, busy process, swallowed Enter, delayed prompt, and wrong-label cases.
  • Existing mx-backend, mx-backend-tmux-smoke, mx-actor-state, mx-peek callers, and mx-tmux-submit-busy tests against both implementations.
  • Process-leak and timeout assertions after every failed backend call.

Documentation and verification

Update docs/architecture.md with the typed backend boundary.

Update docs/tmux-backend.md and docs/verification/runtime-backends.md only after real tmux evidence is recorded.

Do not claim Herdr or cmux Rust support in operator documentation yet.

Definition of done

  • The facade and tmux behavior have differential parity.
  • Real tmux tests pass on Linux and macOS where supported.
  • Actor-state and peek output remain exact and bounded.
  • Herdr and cmux can implement the trait without changing its safety model.
  • The general backend default remains legacy pending Portions 05 and 06.
