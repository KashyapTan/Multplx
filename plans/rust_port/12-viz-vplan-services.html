Viz and vplan Services

Replace the Node loopback servers and shell controllers with Rust services while freezing browser assets, port selection, tokens, paths, idle lifetime, run records, and atomic vplan confirmation behavior.

Portion 12 of 13 Effort: High Risk: Medium Incremental Rust migration

Overview

This portion removes the remaining Node service runtime from viz and vplan without combining the server migration with a UI redesign.

Static assets remain unchanged so HTTP, lifecycle, and persistence parity can be tested independently.

Freeze the front end

Do not change share/viz/ or share/vplan/ during protocol parity. A service and UI rewrite in one portion would make failures difficult to attribute and visual differences impossible to isolate.

Target service design

LISTENERLoopback only, twenty-port probe, bounded connections, and explicit idle timer.
ROUTERSmall fixed route table with method, body, path, and content-type bounds.
IDENTITYPrivate run record, PID identity, token, artifact hash, home, state, and port.
PERSISTENCECanonical roots, no traversal, atomic confirm, response-before-exit, and stale cleanup.

Implementation steps

  1. Freeze HTTP and run-record contracts.Capture routes, methods, status codes, headers, MIME types, injected bytes, token location, port selection, idle timing, and cleanup order.
  2. Implement a minimal bounded HTTP layer.Bind only 127.0.0.1, cap headers and bodies, reject unsupported methods, avoid directory listing, and close malformed connections.
  3. Port viz snapshot serving.Keep GET-only behavior, pull-through refresh bounds, canonical artifact roots, cache timing, and no control actions.
  4. Port viz lifecycle CLI.Preserve singleton idempotency, private run record, identity-bound status and stop, stale cleanup, and URL-only serve output.
  5. Port vplan review serving.Preserve relative asset rewriting, SDK injection, token-authenticated confirm, existing comment merge, body bounds, and one-shot exit.
  6. Port vplan lifecycle CLI.Keep self-check hashes, artifact-under-root validation, record cleanup, comments JSON, exact stop identity, and stale-record behavior.
  7. Run browser and protocol parity.Compare responses byte for byte where stable and visually inspect representative artifacts with unchanged assets.
  8. Remove Node from these paths only.Do not remove Node from bootstrap until Portion 13 proves no retained integration needs it.

Test plan

  • Existing mx-viz and mx-vplan suites against both implementations.
  • HTTP tests for every route, wrong method, missing or wrong token, oversized body, invalid path, encoded traversal, symlink escape, port collision, disconnect, and idle timeout.
  • Run-record tests for mode, stale PID, reused PID, changed token, changed artifact, concurrent serve, and identity-bound stop.
  • Atomic vplan confirmation tests with kill points before write, after rename, after response, and before record cleanup.
  • Snapshot cache timing and bounded child-process tests.
  • Visual comparison of new, review, comments, viz empty, viz active, and artifact-link states.

Documentation and instruction updates

Update docs/viz.md, docs/vplan.md, docs/vplan-authoring.md, architecture, configuration dependencies, and command header pointers.

Definition of done

  • All four owned files run through Rust by default.
  • Loopback, port, token, path, record, timeout, and atomic-write behavior match.
  • Static browser assets are unchanged.
  • No Node process is required for viz or vplan.
  • Portion 13 may remove the old Node service files after repository-wide reference checks.
