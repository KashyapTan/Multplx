Task and Daemon Lifecycle

Port the end-to-end lifecycle for briefs, pending replies, sends, isolated task spawn, daemon homes, safe synchronization, supervision, teardown, and project memory without crossing Multplx's destructive boundaries.

Portion 7 of 13 Effort: Very High Risk: High Incremental Rust migration

Overview

This portion is the first full orchestration slice built on Rust state and backend layers.

It owns the paths that create, steer, synchronize, and retire work, so every mutation requires typed identity, transactional publication, and destructive-target proof.

Transaction boundaries

PREPAREValidate identifiers, authority, project, profile, tools, paths, and current durable state.
ACQUIREClaim worktree, backend endpoint, home lease, or mutation lock with exact identity.
PUBLISHAtomically write metadata, registry, backlog, pending reply, and status-visible records.
RECOVERReconcile partially acquired resources and never tear down unlanded or unverified work.
Destructive path rule

Every recursive removal target must be an explicit, validated, canonical child of an allowed root. No unresolved environment variable, broad home, glob, symlink escape, or inferred endpoint may reach deletion or kill.

Implementation steps

  1. Port brief creation.Preserve task ID validation, existing-file refusal, delivery versus scout content, marker instructions, lab option, and private-home location.
  2. Port pending replies and correlated reporting.Keep correlation identity, parent ownership, wrong-home detection, bounded recovery, escalation, and idempotent completion.
  3. Port send.Resolve metadata and backend once, validate expected labels and harness, send literal text, submit with acknowledgement, and publish marked pending expectations atomically.
  4. Port spawn as a resumable transaction.Validate profile and headroom, acquire a real isolated worktree, ensure project memory, create the backend task, publish metadata, launch the harness, and record backlog state.
  5. Port daemon-home provisioning.Preserve leases, transactional seeding, inherited configuration, charter, registry format, isolated home identity, and failed-launch rollback.
  6. Port daemon supervision.Keep AFK presence gating, composer safety, exact supervisor target, alarm channel bounds, marked injection, and no self-directed work.
  7. Port sync and update.Keep clean fast-forward-only behavior, local-HEAD daemon sync, origin sync, branch safety, dirty and diverged refusal, and summary output.
  8. Port teardown.Preserve landed proof, active endpoint checks, git-lock safety, daemon-child inspection, registry removal, state retirement, and refusal to discard unlanded work.
  9. Port upstream review and project memory helper.Keep fetch-only scratch behavior, ancestry validation, relevance mapping, record locking, and project-write boundaries.
  10. Cut over lifecycle commands together.Do not mix Rust spawn with legacy teardown or legacy spawn with Rust teardown during normal operation.

  • Crash injection after each acquired resource and before or after each durable publication.
  • Concurrent spawn, duplicate task ID, worktree collision, endpoint label collision, headroom queue, daemon reread, and sync contention.
  • Destructive-target adversarial cases for symlinks, ancestors, root aliases, missing metadata, stale locks, dirty worktrees, unique detached commits, and nested homes.
  • Real tmux and Herdr lifecycle smoke coverage plus cmux where the existing lane permits.
  • Rollback tests proving a failed preparation leaves no false live task and no leaked removable resource.

Definition of done

  • All thirteen lifecycle files run through Rust by default.
  • Spawn, send, daemon, sync, update, and teardown compose without shell-library sourcing.
  • Crash recovery cannot lose a task, duplicate a published identity, or remove unlanded work.
  • Every recursive removal and process signal is identity-bound.
  • Portion 08 can supervise Rust-created tasks and daemon homes.
