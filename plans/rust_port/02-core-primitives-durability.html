Rust Port 02 · Multplx

Core Primitives and Durability

Replace the shared shell foundations with typed Rust modules for safe paths, atomic files, process identity, locks, wake records, classification, journals, supervision predicates, and deterministic rendering.

Portion 2 of 13 Effort: Very High Risk: High Incremental Rust migration

Overview

This is the foundational behavior port.

Later lifecycle, watcher, delivery, and service commands depend on these primitives, so this portion prioritizes correctness, fault recovery, and byte compatibility over breadth.

Do not cut over callers early

Rust primitives may be exercised through tests and dedicated compatibility commands, but shell callers remain authoritative until the entire primitive cluster passes concurrency, crash, and differential tests.

Target design

IDENTIFIERSValidated task, home, pane, record, and path components.
FILESYSTEMPrivate create, same-directory temporary write, mode, flush, rename, and recovery.
PROCESSPID plus portable identity, owned-child lifecycle, bounded signals, and reaping.
POLICYPure typed classification and transition functions with deterministic rendering.

Separate pure decisions from operating-system effects.

Use injected clocks and process probes so unit tests do not depend on sleep or live PIDs.

Represent existing line records with typed structs while preserving their exact on-disk bytes.

Implementation steps

  1. Inventory contracts and side effects.For every function, capture accepted inputs, stdout, stderr, return status, globals read or written, files touched, permissions, and platform branches.
  2. Implement identifiers and path boundaries.Validate components before joining them, canonicalize existing ancestors, and distinguish paths that may be absent from paths that must already exist.
  3. Implement atomic and private file operations.Match same-directory rename, modes, truncation behavior, partial-write recovery, and cleanup without following unsafe links.
  4. Implement process identity and locks.Preserve Linux and macOS identity sources, stale-owner rechecks, acquisition races, owner-directory publication, and safe release.
  5. Port pure classifiers and renderers.Translate status, signal precedence, composer, transition, scope, and supervision rules as exhaustive enum matches.
  6. Port wake and journal writers.Prove concurrent append, queue restoration, deduplication, annotation ordering, best-effort journal failure, and lock recovery.
  7. Expose compatibility subcommands.Let black-box tests exercise Rust primitives without switching production callers.
  8. Run the deletion precheck but retain legacy files.Confirm all direct callers are known, then leave the shell sources until their owning portions cut over.

Fault and concurrency matrix

Failure pointRequired result
Before temporary writeNo published file and no false success.
During write or mode applicationOld published record remains valid and private.
After rename but before caller completionRecovery recognizes the published state and does not duplicate the transition.
PID reused between checksIdentity mismatch prevents signaling, cleanup, or lock theft.
Two queue or lock writers raceExactly one owner publishes, and no committed row is lost.
Malformed or oversized recordRead fails closed with bounded diagnostics.
Journal append failsAuthoritative state succeeds or fails according to its own contract, never the journal's.

Test plan

  • Rust unit and property tests for identifiers, record round trips, malformed input, path traversal, and transition tables.
  • Concurrency tests for lock acquisition, wake append, drain restore, and journal append.
  • Fault injection at every publication boundary.
  • Existing mx-composer-*, mx-journal, mx-lock-override, mx-signal-precedence, mx-transition-lib, mx-wake-queue, mx-watcher-lock, mx-tmux-submit-busy, and gate-refusal tests against both implementations.
  • Stock macOS and Linux path, stat, mode, process, and signal cases.

Documentation and instruction updates

Update architecture owners only when a Rust module becomes authoritative.

Keep current command paths in skills and operator docs because no top-level lifecycle command cuts over in this portion.

Add module-level Rust documentation for every contract transferred from a script header.

Definition of done

  • All eighteen legacy files have a named Rust module and parity evidence.
  • No state format, output ordering, permission, or refusal path differs.
  • Concurrent and killed-process tests pass repeatedly.
  • Later portions can depend on stable Rust APIs rather than shell globals.
  • Legacy libraries remain available until their final shell callers move.
