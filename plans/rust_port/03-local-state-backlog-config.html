Rust Port 03 · Multplx

Local State, Backlog, and Configuration

Port the local mutable records that route work and preserve configuration, while keeping every current Markdown, line, JSON, inheritance, and operational-input format unchanged.

Portion 3 of 13 Effort: High Risk: High Incremental Rust migration

Overview

This portion moves bounded local state management onto the Rust durability layer from Portion 02.

It deliberately excludes decisions, overrides, workflows, task spawning, and delivery so backlog and configuration behavior can be proven in isolation.

No data migration

The first Rust implementation reads and writes existing homes in place. A typed internal model does not authorize JSON conversion, reordered fields, rewritten Markdown, normalized whitespace, or a new schema version.

Target design

validated home paths
  ├─ BacklogStore
  │    ├─ parse current Markdown
  │    ├─ lock + reread
  │    ├─ apply one typed mutation
  │    └─ render + atomic publish
  ├─ ProjectRegistry (read-only)
  ├─ InheritancePlanner
  │    ├─ validate source and destination homes
  │    ├─ compute bounded copy plan
  │    └─ publish per-file result
  └─ OperationalInput codec
       ├─ versioned envelope
       ├─ closed kind vocabulary
       └─ exact payload preservation

Implementation steps

  1. Build golden parsers.Use existing backlog, project registry, config, shared-maintainer, and operational-input fixtures plus generated malformed cases.
  2. Separate parse, validate, mutate, and render.Read-only operations must never acquire mutation authority or repair malformed state.
  3. Port backlog transactions.Lock, reread under lock, reject stale assumptions, apply one mutation, preserve retention, and publish atomically.
  4. Port daemon handoff as one transaction.Prove the item cannot be present in both homes or lost from both homes across a crash.
  5. Port inherited-material planning.Validate daemon homes, allowlists, symlink boundaries, read-only shared preferences, file modes, and per-target reporting.
  6. Port project-mode lookup.Preserve defaults, accepted modes, yolo parsing, ambiguous names, missing registry behavior, and stdout shape.
  7. Port the operational-input codec.Preserve current kinds, version checks, current-versus-stale classification, literal payloads, and refusal messages.
  8. Cut over this state slice.Switch only these commands after dual-engine filesystem snapshots match.

Test plan

  • Round-trip and golden tests for every accepted backlog and operational-input shape.
  • Property tests for task keys, titles, multiline bodies, unknown fields, duplicate rows, empty files, trailing newlines, and invalid UTF-8 behavior.
  • Concurrent backlog mutations and killed-writer recovery.
  • Two-home fault injection for backlog handoff and configuration push.
  • Existing mx-backlog-lib, mx-backlog-handoff, mx-shared-maintainer-inheritance, mx-project-mode callers, and mx-operational-input tests against both implementations.
  • A no-op diff proving unchanged input is not rewritten merely because Rust read it.
