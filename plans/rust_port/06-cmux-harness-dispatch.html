Overview

Implementation steps

  1. Port cmux authentication and version checks.Read the password fresh, preserve ambient-password precedence, prevent diagnostic leakage, and classify denied versus unavailable states.
  2. Port cmux identity and lifecycle.Keep home labels, scoped titles, workspace and surface lookup, readiness, path, capture, submit, list, and exact kill semantics.
  3. Port harness detection.Preserve verified environment markers, process ancestry, unknown handling, static configuration, daemon pins, model tokens, and effort tokens.
  4. Port primary harness launch.Resolve the real executable without shim recursion, validate the supported adapter, preserve arguments and environment, change only the child cwd, and exec.
  5. Port composite headroom.Model every candidate explicitly, reject incomplete capacity interpretation, preserve strongest-reasoning behavior, and keep durable queue ordering and cancellation.
  6. Port Treehouse installation checks.Preserve version and lease-capability requirements, checksums, supported platforms, modes, and detect-then-consent installation.
  7. Run cross-backend and cross-harness verification.Exercise the same facade contract against tmux, Herdr, and cmux and the same launch contract against all four harnesses.
  8. Cut over the backend and harness layer.Switch only after every supported axis passes; keep task lifecycle commands on their current implementation until Portion 07.

Test plan

  • Existing mx-backend-cmux and cmux smoke tests, including wrong password, missing app, version refusal, target collision, path mismatch, and cleanup.
  • Existing backend facade, autodetect, dispatch queue, headroom, daemon harness model resolution, and launcher-harness callers against both implementations.
  • Real empirical launch checks for Claude, Codex, Cursor, and Pi with exact versions recorded.
  • Candidate-set property tests proving no candidate is omitted, duplicated, or selected by array order on a genuine tie.
  • Queue contention, oldest-first retry, at-limit persistence, cancellation, malformed config, and crash-recovery tests.
  • Treehouse checksum, wrong platform, stale version, missing lease support, and successful install fixtures.

Definition of done

  • The cmux implementation satisfies the same typed backend contract as tmux and Herdr.
  • All four harnesses are empirically verified or a claimed adapter is explicitly blocked.
  • Headroom accounts for every candidate and preserves durable queue behavior.
  • The general backend, harness, and headroom layer runs through Rust by default.
  • Portion 07 can create tasks without sourcing backend or harness shell code.
