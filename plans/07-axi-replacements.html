Plan 07 / 10

Owning the Toolbelt — Replacing the -axi Dependencies

Remove Multplx's hard dependency on the upstream author's private npm toolbelt (gh-axi, tasks-axi, quota-axi, chrome-devtools-axi). Wrappers over real tools collapse to the real tool; real logic becomes small in-repo scripts we own. The fifth toolbelt member, lavish-axi, is a genuinely distinct capability and gets its own standalone module — see Plan 08 (vplan).

Phase 5 Effort: Medium Risk: Medium UPDATE_PLAN §8.2 UPDATE_PLAN §8.7 (sequencing)

Overview

Firstmate leans on five npm-installed CLIs written and published by the upstream author — the -axi toolbelt. All five are probed by bin/fm-bootstrap.sh (its COMMON_TOOLS list at line 516 names gh-axi chrome-devtools-axi lavish-axi tasks-axi quota-axi, with install commands in install_cmd() at lines 489–490), four of them as required tools. That means a fresh Multplx home cannot even pass session-start bootstrap without installing someone else's private npm packages. These are the most firstmate-specific dependencies in the whole tree and the prime candidates to replace.

This plan covers four of the five toolbelt members. lavish-axi (the HTML plan-artifact creator) is deliberately excluded: per UPDATE_PLAN §8.2 and §8.5 it is a genuinely distinct capability, replaced by our own standalone vplan module in Plan 08. Everything else lands here.

Guiding principle (UPDATE_PLAN §8.2)

Every -axi tool is a thin wrapper the upstream author controls. Wherever the wrapper sits on top of a genuine tool we keep (gh), collapse to the underlying tool. Wherever it provides real logic (tasks, quota), reimplement it small and in-repo so we own it — folding it into existing schema/reporting mechanics where responsibility already overlaps, rather than standing up a parallel system.

The four replacements, in the order this plan executes them (§8.7: start with the low-effort gh swap):

  1. gh-axi → official gh CLI (Low effort) — the merge path in bin/fm-pr-merge.sh calls the wrapped tool directly.
  2. chrome-devtools-axi → defer/remove (Deferred) — drop the bootstrap probe now; revisit with a first-class tool only if a task ever needs browser automation.
  3. tasks-axi → mx-backlog-lib.sh (Medium) — an in-repo backlog library over the plain markdown backlog file, reproducing the surface firstmate actually consumes.
  4. quota-axi → mx-headroom.sh (Medium) — our own dispatch-capacity signal, combining local machine resources with API rate headroom (capacity model decided by the maintainer 2026-07-26).

Goals & Non-goals

GoalsNon-goals
  • Zero -axi npm packages required to bootstrap or run Multplx.
  • PR merge path uses the official gh CLI directly (gh pr merge / gh api).
  • An in-repo backlog library (mx-backlog-lib.sh) that reproduces the read/write/query surface firstmate consumes from tasks-axi.
  • An in-repo headroom check (mx-headroom.sh) producing a machine-readable dispatch-capacity signal.
  • All -axi bootstrap probes and install_cmd() entries removed.
  • Graceful degradation preserved: the existing manual-backlog fallback stays live while the new lib is built incrementally.
  • Replacing lavish-axi — that is Plan 08 (vplan).
  • Feature-parity clones of the upstream tools. We reproduce only the surface our workflow uses (UPDATE_PLAN §8.2: "functional parity for our workflow, not a clone of every feature").
  • Building browser automation. chrome-devtools-axi is removed, not replaced, until a real need appears.
  • Owning the push/merge credential model — gh invocation moves here, but who runs it (a credentialed non-agent process, not an actor) is Plan 09's contract.
  • Re-litigating the quota model — the maintainer decided 2026-07-26: combined local machine resources + API rate headroom (§8.2 called this "a policy decision as much as a port", and it was made as one).

Target design in Multplx

1. gh-axi → official gh CLI (Low effort)

Current state. gh-axi is described upstream as the "canonical GitHub interface", but firstmate uses it for exactly one thing: merging PRs at bin/fm-pr-merge.sh:84. Everything else GitHub-shaped already goes through the official gh CLI (fm-pr-check.sh, fm-pr-poll.sh, gh auth status in bootstrap). We keep gh anyway — it's genuine infrastructure (UPDATE_PLAN §8.3) — so the wrapper adds nothing.

Replacement design. This is the cleanest swap in the whole plan: drop the wrapper, call the tool it wraps. In Multplx's bin/mx-pr-merge.sh, line 84 becomes:

# before (firstmate)
gh-axi pr merge "$PR_NUMBER" --repo "$PR_OWNER/$PR_REPO" "${merge_args[@]+"${merge_args[@]}"}" "$@"

# after (Multplx)
gh pr merge "$PR_NUMBER" --repo "$PR_OWNER/$PR_REPO" "${merge_args[@]+"${merge_args[@]}"}" "$@"

gh pr merge natively accepts --squash/--merge/--rebase and --repo owner/repo, so the existing default-method logic, repo-override rejection, and URL-parse flow survive intact; only argument shapes that differ between gh-axi and gh need adjustment during the port (verify against current gh pr merge --help rather than memory). Anything gh pr merge can't express falls back to gh api calls — still the official CLI, still the credentials gh auth already manages.

Plan 09 tie-in. Under Multplx's least-privilege model (Plan 09), merge and push are owned by a separate, credentialed non-agent process — an actor never holds remote write credentials. Moving the merge onto plain gh is a prerequisite: the credentialed process invokes a standard, auditable CLI rather than a third-party wrapper.

Steps. (a) Swap the invocation in mx-pr-merge.sh; (b) remove gh-axi from bootstrap's COMMON_TOOLS and install_cmd(); (c) rewrite the AGENTS.md §3 line to "use gh for GitHub"; (d) adapt tests/fm-pr-merge.test.sh to mock gh instead of gh-axi.

Replacement design — bin/mx-backlog-lib.sh new. A sourced bash library (matching the fm-*-lib.sh convention) that is the single owner of the backlog markdown format, operating on the same plain file layout firstmate already uses: data/backlog.md with ## In flight / ## Queued / ## Done sections, - [ ] <key> / - [x] <key> item headers, and two-or-more-space indented body lines. Proposed function surface, one per consumed verb:

mx_backlog_list <file> <limit> <fields>      # compact listing for the session digest
mx_backlog_show <file> <id>                  # full item block
mx_backlog_done <file> <id> [--report p | --note s | --pr url]
                                             # -> ## Done, retention + data/done-archive.md
mx_backlog_ready <file>                      # queued items with cleared blockers
mx_backlog_hold <file> <id> --reason s --kind k
mx_backlog_mv <src> <dest> <id>...           # atomic multi-ID block move (all-or-nothing)
mx_backlog_update <file> <id> --body s --archive-body
                                             # recoverable note rewrite

Key properties ported deliberately, not incidentally: mx_backlog_mv must keep the one-parser guarantee that motivated upstream's delegation (the header comment in fm-backlog-handoff.sh records that a hand-rolled awk mover caused the body-orphaning bug fixed in upstream PR #401 — with the lib in-repo, "one parser" now means this lib and nothing else re-implements block extraction); atomicity via write-to-temp + rename of both files only after both new contents are computed; dependency-strand refusal preserved. The retention constants (done_keep, archive path) move from .tasks.toml into the lib's documented defaults (overridable via MX_* env or a one-line config), and .tasks.toml and all version-gating are dropped.

Incremental build with graceful degradation. Firstmate already degrades gracefully when tasks-axi is absent (manual hand-editing path, config/backlog-backend=manual, the title-line fallback in fm-session-start.sh). Keep exactly that fallback as the safety net while mx-backlog-lib.sh is built verb-by-verb: each consumer (mx-session-start.sh, mx-teardown.sh, mx-backlog-handoff.sh) switches from "compatible tasks-axi else manual" to "mx-backlog-lib else manual", one call site at a time. When all verbs land, the manual knob remains as an operator preference rather than a compatibility fallback.

Steps. (a) Create mx-backlog-lib.sh with the mv/list/show core; (b) port mx-backlog-handoff.sh to call mx_backlog_mv (its fleet-level validation — secondmate-home proof, section classification, indent checks — is already local and survives unchanged); (c) port the session-start compact listing; (d) port teardown's done/ready emission; (e) add hold/update --archive-body; (f) delete fm-tasks-axi-lib.sh, .tasks.toml, and the bootstrap probes; (g) rewrite AGENTS.md §10 and docs/configuration.md to name the lib as schema owner.

3. quota-axi → own headroom check (Medium — capacity model decided)

Current state. quota-axi reports quota/headroom used for dispatch decisions. It is a required bootstrap tool (COMMON_TOOLS), and AGENTS.md §4 makes the broker-equivalent run quota-axi --json at every dispatch-profile intake, evaluate every configured harness/model candidate against the output, pick the candidate with the most real headroom, and stop-and-report rather than guess when any candidate's quota data can't be established — plus an interim "use the weakest applicable remaining headroom" rule for window interpretation.

Replacement design — bin/mx-headroom.sh new. UPDATE_PLAN §8.2 is explicit that this is "a policy decision as much as a port": we first had to define what dispatch capacity means for Multplx rather than copying upstream's model. Three candidate models were presented; the maintainer decided on 2026-07-26 (see the decided callout below):

ModelSignal sourcePros / Cons
A. Max concurrent actors — rejected as the primary modelCount live actor endpoints (from state/*.meta + backend liveness) vs. a configured cap, e.g. config/max-actors.Deterministic, zero external calls, trivially testable. Ignores that some actors are far heavier than others — which is why it lost; a concurrency cap may still be derived from the resource limits.
B. Local resource limits — chosen (half of the composite)Load average / free memory / open-session count on the host.Protects the machine directly. Noisy, platform-dependent, and only a proxy for what actually throttles us (model quota) — which is why it is paired with C.
C. API rate headroom — chosen (half of the composite)Per-provider usage windows (what upstream's model approximates), read from provider usage endpoints or harness-local accounting.Closest to the real constraint and to the existing §4 contract. Hardest to build honestly; risks reinventing the wrapper we just removed.
Decided · 2026-07-26

The capacity signal is the B + C composite: mx-headroom.sh reads local machine resources — CPU, memory, and load via sysctl/vm_stat on macOS and /proc on Linux — and combines them with an API-rate-headroom input; the tighter of the two signals bounds dispatch. Model A (max concurrent actors) is rejected as the primary model, though a concurrency cap may still be derived from the resource limits. One detail remains design work — a concrete source for the API side (e.g. a configurable budget/counter) — but that is an implementation question, not a model choice.

With the model decided, the interface is fixed: mx-headroom.sh --json prints one machine-readable capacity object and exits 0, e.g.

{
  "model": "local+api",             // the decided composite: local resources + API rate headroom
  "capacity": 4,                    // dispatch slots under the tighter of the two signals
  "in_use": 3,
  "available": 1,
  "candidates": {                   // per-harness/model detail from the API-headroom side
    "claude": { "available": 1, "window": "…" }
  },
  "at_limit": false
}

Consumers: (a) the dispatch-time check — the broker's intake contract in Multplx's AGENTS.md §4 rewrites "run quota-axi --json" to "run mx-headroom.sh --json", keeping the account-for-every-candidate, stop-and-report-on-unknowns, and no-silent-downgrade rules; (b) bootstrap — the quota-axi presence probe is replaced by a self-check that mx-headroom.sh --json executes and emits valid JSON. At or over the limit, the signal says so ("available": 0, "at_limit": true) and dispatch must refuse rather than spawn — and, per the 2026-07-27 scope addition below, park the request rather than forget it.

Scope addition · 2026-07-27

Approved by the maintainer 2026-07-27: refusal must not discard intent. When the headroom signal says at_limit, the dispatch request is parked, not dropped — the broker writes one small record per parked task into a durable on-disk queue at state/.dispatch-queue/ (task id, project, requested profile, enqueue time; plain restart-reconstructable files, the same design virtue as the rest of the state dir) and tells the maintainer the task was queued. Draining needs no new process: the existing watcher's poll loop checks the queue when it already wakes, re-runs mx-headroom.sh, and dispatches the oldest parked task when capacity has freed — FIFO, at most one per poll cycle to avoid a thundering-herd respawn; while the signal still says at_limit, nothing is dispatched. The maintainer can inspect and cancel parked entries (mx-headroom --queue or similar). Context the maintainer asked about (verified 2026-07-27 against the firstmate checkout): upstream firstmate has no numeric concurrency cap anywhere — capacity was delegated entirely to quota-axi's dynamic API-quota headroom, and with quota-axi absent there is no capacity check at all. Multplx's composite model is therefore the system's first real capacity ceiling, which is exactly why refusing-and-forgetting at the limit would be a usability regression rather than parity.

Steps. (a) Land mx-headroom.sh with the JSON contract, implementing the decided composite: local-resource readings (CPU/memory/load via sysctl/vm_stat on macOS, /proc on Linux) combined with the API-rate-headroom input; (b) rewrite the §4 dispatch contract; (c) replace the bootstrap probe; (d) settle the one remaining implementation detail — the concrete API-usage source (e.g. a configurable budget/counter) — and until it lands, the API side reports a conservative configured budget and dispatch says so rather than calling itself fully quota-informed (mirroring upstream's own stop-and-report ethic). The upstream interim weakest-headroom rule is dropped along with the tool it interpreted.

4. chrome-devtools-axi → defer / remove

Current state. Browser automation for tasks; optional and per-task, but still listed in bootstrap's COMMON_TOOLS and install_cmd(), and named in AGENTS.md §3 ("chrome-devtools-axi for browser work").

Replacement design: none, on purpose. It is not core to the orchestration loop. Remove the bootstrap probe and the install_cmd() entry now, and delete the §3 mention. If a task ever genuinely needs browser automation, pick a first-class tool at that point — Playwright/Puppeteer, or an MCP browser tool exposed through the harness — rather than reviving this wrapper. No file in bin/ calls it, so removal is probe-and-prose only.

Risks & open questions

Risk — backlog format drift

mx_backlog_mv reimplements the block-move semantics upstream deliberately centralized in tasks-axi after a body-orphaning bug (upstream PR #401). Mitigation: mx-backlog-lib.sh is the one and only parser (the handoff script's read-only classifier is folded in or kept strictly header-line-only), and the golden-file suite covers byte-exact fidelity including the indented pseudo-heading and blank-separator cases the upstream header comment calls out.

Decided · 2026-07-26 — dispatch-capacity model

"Quota" for Multplx is the B + C composite: local machine resources (CPU/memory/load via sysctl/vm_stat on macOS, /proc on Linux) combined with API rate headroom. Rejected: A (max concurrent actors) as the primary model — though a concurrency cap may still be derived from the resource limits. The one item still open is an implementation detail, not the model: where the API-side usage data comes from without rebuilding the wrapper we removed (e.g. a configurable budget/counter) — that stays flagged as remaining design work.

Open question — gh flag parity

gh-axi's exact pr merge flag surface isn't fully documented in the firstmate tree; extra args forwarded by callers today may not map 1:1 onto gh pr merge. Verify against live gh pr merge --help during the port and route any gaps through gh api.

Note — deferred capability

Removing chrome-devtools-axi leaves Multplx with no browser-automation story. That is intentional: revisit with Playwright/Puppeteer or an MCP browser tool only when a concrete task needs it.
