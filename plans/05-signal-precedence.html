Plan 05 / 10

Explicit Signal Precedence in the Classifier

Different backends produce different-quality signals about the same actor. Add one documented precedence rule to the classify library — harness-native event > schema-validated self-report > text/regex heuristic — and apply it uniformly across every backend, replacing today's implicit, per-backend handling.

Phase 3 Effort: Low–Medium Risk: Medium — touches the state oracle; regressions here misroute escalations UPDATE_PLAN §5

Overview

The supervision loop judges each actor from up to three signal sources of very different reliability:

  • Harness-native events — near ground truth. Herdr's native done/blocked agent-state events, already wired in for that backend: the runtime itself reports the agent's state over its event stream, no inference involved.
  • Schema-validated self-report — good, but still self-reported. A status line written through mx-report / the MCP report_status tool (from Plan 03): guaranteed well-formed, but the agent can still be wrong about itself.
  • Regex busy-signature on pane text — weakest, most prone to false positives. For tmux and cmux, which have no native busy primitive (upstream also zellij and orca, both deleted in plan 01), the watcher matches pane text against BUSY_REGEX (default 'esc (to )?interrupt|Working\.\.\.|Ctrl\+c:cancel' in fm-watch.sh) — literally grepping the screen for the harness's "busy" UI hint.
Decided · 2026-07-26

Backend pruning is settled: Multplx keeps tmux, cmux, herdr only — zellij and orca are deleted in plan 01 (harnesses are likewise pruned to claude/codex/pi). For this plan that shrinks the heuristic tier's surface: the regex busy-signature path covers exactly two backends (tmux and cmux), and herdr stays the sole native-event producer. Where upstream-describing prose below enumerates tmux/zellij/orca/cmux, that records firstmate as-is; Multplx's reality is tmux and cmux.

When two of these disagree about one task at the same moment, there is currently no single documented rule for which one wins — it's handled implicitly and inconsistently per backend. The reconciliation oracle fm-crew-state.sh has its own internal order (validation run-step, then pane, then status log), the herdr push-transition path has another (a declared paused: status line absorbs a native blocked event), and the watcher's stale path has a third ("an active run-step or busy pane outranks even a captain-relevant log line", per the fm-watch.sh header). Each order is locally reasonable; collectively they are three different answers to the same question.

The fix, per UPDATE_PLAN §5: add one explicit precedence order to the classify library (fm-classify-lib.sh → mx-classify-lib.sh) — harness-native event > schema-validated self-report > text/regex heuristic — documented in the library header and applied uniformly regardless of which backend a given task happens to be running on. The classify lib is already the deliberate single home for shared triage policy ("the overlapping triage policy lives in one place instead of two copies that can drift apart", per its own header); this plan extends that charter from vocabulary to precedence.

Risk is Medium and deserves respect: this library and its consumers are the state oracle for the whole system. A wrong precedence call misroutes escalations — either the maintainer gets woken for work that is genuinely still running, or a finished/stuck actor is silently absorbed. The mitigation is a conflict-matrix test suite that pins every pairing before any consumer is rewired.

Goals & Non-goals

GoalsNon-goals
  • One documented precedence order in mx-classify-lib.sh's header: native event > schema-validated self-report > regex heuristic.
  • One shared decision function implementing it, used by every consumer (the crew-state oracle's successor, the push-transition handler, the watcher's stale/no-verb paths, the away-mode daemon).
  • Uniformity across backends: the same task state, observed through herdr or through a tmux pane, resolves conflicts by the same rule.
  • Conflict-matrix tests covering every same-moment disagreement pairing, plus a documentation assertion that the header states the order.
  • No change to the signal sources themselves: the herdr event stream, mx-report, and the busy regex are all produced exactly as before.
  • No change to the event-log model: status stays an append-only event stream; status_open_decisions' keyed fold is untouched.
  • No change to wake latency or the poll/nudge mechanics (Plan 04).
  • No new backend capabilities — backends without native events simply have an empty tier 1.
  • Not a rewrite of mx-crew-state.sh: its run-step attribution, CI log-tail override, and meta resolution stay as-is; only the conflict-resolution seams change.

Current state in firstmate

How classification works today

bin/fm-classify-lib.sh (414 lines) is the shared wake classifier sourced by both the always-on watcher (bin/fm-watch.sh) and the away-mode daemon (bin/fm-supervise-daemon.sh). It owns the verb vocabulary (done:/needs-decision:/blocked:/failed: = captain-relevant; working:/paused:/resolved: = nonterminal), the keyed-decision fold, and the absorb classification: crew_absorb_class <id> delegates to bin/fm-crew-state.sh for one authoritative current-state line and maps it to working / paused / none; crew_is_provably_working is the predicate behind "absorb only when provably working".

bin/fm-crew-state.sh (629 lines) derives that line in a fixed internal order, documented in its header:

1. state/<id>.meta → worktree, backend target, kind
2. attributed validation run-step (branch AND code identity must match)
       — AUTHORITATIVE when present: running/fixing/ci → working,
         awaiting_approval/fix_review → parked, passed → done, failed → failed
3. status-log reconcile: a needs-decision/blocked last line that the run
   moved past is flagged "superseded" (stale), never trusted
4. no run at all → pane busy state, then the status log's last verb
5. missing meta / torn-down worktree → unknown · none

So within the oracle there IS a precedence — pipeline evidence beats pane, pane beats log — but it is private to this script and it never had to rank a native backend event against anything, because those flow through an entirely different path:

How herdr native events are wired today

Herdr's pane.agent_status_changed events are normalized by bin/backends/herdr.sh (fm_backend_herdr_wait_transition) into the backend-neutral record shape owned by bin/fm-transition-lib.sh — <pane_id>\t<workspace_id>\t<from>\t<to>\t<agent> with the shared agent-state vocabulary idle|working|blocked|done|unknown and a single status→action policy table (fm_transition_policy). The watcher consumes them via event_wait_or_sleep → handle_push_transition in bin/fm-push-transition-lib.sh. Herdr also answers fm_backend_busy_state natively (semantic busy/idle/unknown in bin/fm-backend.sh); tmux/zellij/orca/cmux return unknown, which cues the watcher's pane-hash + FM_BUSY_REGEX fallback (in Multplx, only tmux and cmux survive the plan 01 pruning).

And here is the inconsistency, live in handle_push_transition:

# bin/fm-push-transition-lib.sh — a NATIVE herdr event arrives, but…
if status_is_paused "$(last_status_line "$STATE/$task.status")"; then
  triage_log "absorbed push $to (declared pause, awaiting external): $window"
  …return   # ← the SELF-REPORTED paused: line outranks the native event
fi

…while the watcher's stale path does the opposite ranking: "a provably-working stale is ALWAYS absorbed … an active run-step or busy pane outranks even a captain-relevant log line" (fm-watch.sh header) — there the weakest signal (regex pane-busy) outranks a self-reported terminal verb. Two consumers, two opposite implicit orders.

Target design in Multplx

The rule (verbatim, one owner)

Precedence — to be stated in the mx-classify-lib.sh header
When signals about one task disagree at the same moment:
1. harness-native event (the runtime's own agent-state stream, e.g. herdr done/blocked)
> 2. schema-validated self-report (a status event written through mx-report / report_status)
> 3. text/regex heuristic (pane busy-signature match, MX_BUSY_REGEX)
Applied uniformly across all backends. A backend without a tier simply contributes nothing at that tier.

Where it slots in

One new pure function in mx-classify-lib.sh, alongside the existing predicates:

# mx_signal_resolve: rank same-moment signals about one task.
#   $1 native      - harness-native agent state (idle|working|blocked|done|unknown, '' if none)
#   $2 self_report - last schema-valid status verb (working|paused|blocked|needs-decision|done|failed|resolved, '' if none)
#   $3 heuristic   - regex/pane verdict (busy|idle|unknown, '' if none)
# Prints the winning tier and verdict, e.g. "native:done", "self-report:blocked",
# "heuristic:busy", or "none". Pure function of its arguments - no file reads -
# so the conflict matrix tests it exhaustively without a live backend.

Consumers are then rewired to route their existing readings through it instead of hand-ordering them:

  • mx-crew-state.sh (the oracle): gains a native-event tier at the top of its fallback chain — before the pane read, it asks mx_backend_busy_state/the backend's level-read for a native agent state and, when one exists, resolves conflicts with the log via mx_signal_resolve. Its deterministic run-step attribution stays above all three tiers (see the open question on run-step ranking below — the run-step is pipeline evidence, not one of §5's three signal classes, and today it already outranks everything).
  • handle_push_transition (push path): the paused-absorbs-native check is replaced by mx_signal_resolve native="$to" self_report="$last_verb" … — under the documented rule a native blocked now outranks a self-reported paused: and surfaces. This is a deliberate behavior change (see Risks); the declared-pause cadence still applies when the only evidence of idling is the pause line itself.
  • Watcher stale/no-verb paths: crew_absorb_class keeps its shape but its verdict now reflects the shared ranking: a regex-only busy match no longer overrides a schema-valid terminal self-report (done:/blocked: surfaces even if the pane still matches the busy signature); a native working state still absorbs.
  • Away-mode daemon: no separate wiring — it already consumes crew_absorb_class and the shared predicates, so it inherits the rule, which is exactly why the rule lives in the classify lib.

What counts as a "schema-validated self-report"

UPDATE_PLAN §5 defines tier 2 by reference to §3. The simplest faithful reading, proposed here: a status line whose leading verb parses (via status_line_verb) into the Plan 03 closed enum counts as tier 2 — no wire-format change, no per-line provenance marker. Since Plan 03 makes mx-report the only instructed write path, well-formed lines are validated lines in practice; a malformed line has no verb tier and simply never outranks anything (today's behavior). Whether to add an explicit provenance marker instead is carried as an open question.

Broker contract & documentation updates

Signal precedence changes what the broker treats as current truth, so its ordering must be explicit in the always-loaded contract and stated in full in only one owner.

  • AGENTS.md: state the concise precedence rule and point to the classification owner; update every monitoring and reconciliation instruction that currently implies the old ordering.
  • docs/architecture.md and docs/watcher-continuity.md: explain how run state, validated reports, native events, and regex heuristics interact at the system level.

  • Herdr eventwait tests (tests/fm-backend-herdr-eventwait-smoke.test.sh, fm-backend-herdr-eventwait.test.py) — if they pin the declared-pause absorb of a native blocked event, that case flips to surface-with-overruled-tier-logged. Verify during step 8; producers and record shapes are untouched, so nothing else there moves.

(c) New tests to write — tests/mx-signal-precedence.test.sh

  • Pure-function conflict matrix over mx_signal_resolve (sourced directly, like the classify predicates in the triage tests) — every pairing and the three-way case:
    • native done + regex busy → done (native wins over heuristic);
    • native blocked + self-report paused/working → blocked (native wins over self-report);
    • self-report blocked + regex busy → blocked (self-report wins over heuristic);
    • self-report done + regex busy → done;
    • regex-only busy → heuristic used (working/absorb) — the fallback still functions on tmux and cmux;
    • native working + self-report done → working (precedence is symmetric, not surface-biased);
    • all three present and disagreeing → native wins; empty tiers skipped; all-empty → none.
  • Behavioral spot-checks through the real consumers, using the existing stub seams (FM_CREW_STATE_BIN, the wake-helpers watcher harness): the push path surfaces a native blocked past a declared pause; the stale path surfaces a validated done: despite a busy-regex pane; a regex-only busy stale is still absorbed.
  • Documentation assertion: grep bin/mx-classify-lib.sh's header comment block for the stated order (the phrase native event > schema-validated self-report > text/regex heuristic), failing if the rule is implemented but undocumented — the doc is part of the contract.

Risks & open questions

Risk — this is the state oracle (the reason for the Medium rating)
Every escalation-routing decision flows through the classify lib and its consumers. A precedence bug either wakes the maintainer for actors that are genuinely mid-work (noise, erodes trust in wakes) or silently absorbs a finished/stuck actor (the exact failure the absorb-only-when-provably-working design exists to prevent). Mitigations: pure-function resolver tested exhaustively before consumers move; tests-first landing order; the two deliberate behavior flips isolated to named assertions; the run-step tier untouched.
Deliberate behavior change — native events now pierce a declared pause
Today handle_push_transition absorbs a native blocked when the log declares paused:; under the documented rule it surfaces. Rationale: the pause declaration is a self-report about the future ("expect me to idle"), while the native event is ground truth about now ("the agent is waiting on a human") — and a paused actor whose runtime says blocked is exactly a case worth one look. If this proves noisy for legitimately paused actors whose harness idles as "blocked", the maintainer can revisit with evidence; flagged rather than silently decided.
Open question — where does the validation run-step rank?
UPDATE_PLAN §5 names exactly three signal classes; the deterministic validation run-step (deep-review pipeline evidence in mx-crew-state.sh) is none of them, and today it outranks everything. This plan keeps it above tier 1 — it is externally observed process state, not an agent signal — but that placement is an interpretation, not spec. Confirm with the maintainer before step 3 lands.
Open question — tier-2 membership without provenance
Proposed: any well-formed enum verb counts as schema-validated (no wire change). Alternative: mx-report stamps a provenance marker per line so hand-written well-formed lines rank lower. The marker adds wire-format churn the reconciliation stack would need to tolerate; recommend the simple reading unless abuse is observed. Maintainer call.
