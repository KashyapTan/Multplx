Plan 01 / 10

Delete the Dead Weight — Outright Dependency Removal

Rip out the firstmate subsystems that serve no purpose in Multplx: the myfirstmate.io social relay (X mode), shellcheck as a standalone top-level lint gate and installer, glab/GitLab forge support, the macOS osascript wedge-alarm notifier — and, per the 2026-07-26 maintainer decision, the zellij and orca backend adapters plus grok and opencode harness support. Pure code removal — no replacements are built in this plan.

Phase 1 Effort: Low–Medium Risk: Low UPDATE_PLAN §8.1

Overview

UPDATE_PLAN §8.1 identifies four dependencies to delete outright, with no replacement. None of them is load-bearing for the core orchestration loop (watcher, classifier, state reconciliation, spawn/teardown, briefs). Removing them first — before any reimplementation work — shrinks the surface every later plan has to touch, which is exactly why §8.7 sequences the deletions ahead of everything else.

The four targets, verified against the actual checkout at /Users/ktanuku/Documents/github/Multplx/firstmate:

  • myfirstmate.io social relay (X mode) — a hosted HTTP relay for X.com/Twitter and Discord mentions. Ships inert; only activates when FMX_PAIRING_TOKEN is placed in the home's gitignored .env. Six bin/fm-x-*.sh scripts (the shared client bin/fm-x-lib.sh alone is 984 lines), plus AGENTS.md §14, the .agents/skills/fmx-respond/ skill, FMX_* env handling in bin/fm-bootstrap.sh, and X-mode notes in docs/configuration.md. Multplx will never run a public social persona.
  • shellcheck as a standalone gate + installer — bin/fm-lint.sh (453 lines, the single lint owner both CI and the upstream no-mistakes gate invoke) and bin/fm-install-shellcheck.sh (36-line pinned-release installer). We delete the standalone installer and mandatory top-level gate, not the ability to lint — see the nuance callout below.
  • glab / GitLab support — optional GitLab MR polling and head-commit reads (merge was never implemented upstream). Multplx is a GitHub-only fork; deleting the GitLab branches collapses the dual-forge abstraction in bin/fm-pr-check.sh, bin/fm-pr-poll.sh, and bin/fm-pr-lib.sh down to GitHub-only, simplifying every PR code path.
  • osascript wedge-alarm notifications — the away-mode "wedge alarm" posts a macOS Notification Center banner when an escalation gets wedged. It is already optional (macOS + away-mode only); the generic command:<cmd> channel escape hatch in the same alarm system covers any future alert need without macOS-specific code.
Nuance — shellcheck's function survives, its plumbing does not

Per UPDATE_PLAN §8.1: shellcheck is "not deleted-and-forgotten — its function moves into our deep-review gate (§6)." The lint step of the deep-review gate (plan 10) owns linting from now on, via the §6.3.1 commands.lint configured-command mechanic or the Tier-2 agent-lint fallback. What this plan deletes is shellcheck as a separate top-level dependency: the pinned installer, the mandatory standalone gate wiring, and the CI step. A project that wants shell linting later simply declares its linter as its commands.lint.

Risk is low because all four subsystems are either opt-in (X mode, wedge alarm), optional (glab), or self-contained with a single well-known consumer (the lint gate's only callers are CI and the upstream contribution pipeline we are dropping anyway). The main care point is the test suite and the test runner's hardcoded file maps, covered in detail below.

A fifth deletion group was added by maintainer decision on 2026-07-26: the zellij and orca backend adapters and the grok and opencode harness support are pruned as well — see the dedicated Backend & harness pruning section below.

Risks & open questions

Open question — does config/wedge-alarm survive?

UPDATE_PLAN §8.1's file column says to remove "the config/wedge-alarm config", but its rationale keeps the generic command:<cmd> escape hatch — which is configured through config/wedge-alarm directives. These can't both hold fully. Recommended reading: remove only the osascript channel; keep config/wedge-alarm as the channel selector for herdr / command: / discard. Confirm with the maintainer before implementation.

Open question — lint gap until plan 10

Between this plan and plan 10, no lint gate runs anywhere (CI or local). If that window is long, consider keeping the ci.yml lint step pointed at a plain shellcheck invocation as a temporary bridge — but that re-adds the dependency §8.1 removes, so default is: accept the gap.

Risk — test-runner map drift

bin/fm-test-run.sh hardcodes deleted test/script names in at least eight locations. Missing one leaves the runner selecting nonexistent shards. Mitigation: step 8 is its own commit-reviewable change, and tests/fm-test-run.test.sh plus a full-suite run gate the merge.

Low blast radius

X mode ships inert (token opt-in), glab is optional (GitLab watches only), the wedge alarm's osascript channel is macOS/away-mode only, and lint's only mandatory consumer is the upstream contribution CI we are not keeping. No core-loop behavior changes.
