Plan 6.5 · Multplx Port

Test Suite Acceleration — Same Proof, Much Shorter Wait

Cut the complete local regression from 52 minutes to 15 minutes or less without deleting tests, weakening assertions, hiding skips, or shrinking production safety timeouts. The work is test infrastructure only: measure the real critical path, split oversized suites at proven isolation boundaries, replace wall-clock waiting with observable conditions and fake clocks, reuse clean fixtures, and teach the runner to schedule the full inventory by audited resource conflicts.

Phase 4.5 Effort: High Risk: Medium Maintainer request · 2026-07-28

Why this plan exists

Plan 06 changed 14 files by 172 additions and 117 deletions, but its complete regression took about 52 minutes per run on the maintainer's machine. The first run exposed seven dormant-contract fixture failures; after repairing them, the required confirmation run consumed another 52 minutes. That feedback cycle is too slow for the remaining port phases, especially plans 07–11, which add substantially more behavior than plan 06.

The suite already has useful infrastructure: one inventory-owning runner, per-script timing markers, JSON timing artifacts, two duration-balanced portable shards, a 26-script proven-isolated set, a dedicated real-Herdr lane, and an exact coverage guard. The problem is that local --all remains entirely serial, --jobs refuses any selection containing one of the 70 unproven scripts, and several very large scripts repeat production-scale waits and expensive repository/process fixtures dozens of times.

Target design

1. A measured contract, not anecdotal optimization

Add docs/mx-test-performance.md plus a machine-readable baseline JSON derived from one clean serial run on the Plan-06 boundary. It records host/tool versions, total wall time, per-family time, the slowest scripts, expected skips, and the one known branch-topology failure separately from performance. Add an opt-in per-case timing helper in tests/lib.sh for the suites being split; it wraps existing test functions without changing their bodies or assertion text.

The performance document owns the baseline, targets, latest accepted proof, and the command used to reproduce each number. The runner remains the single owner of selection, resource classes, scheduling, and timing output.

2. Resource-aware full-suite scheduling

Replace the all-or-nothing proven-isolated gate with an audited resource-conflict manifest owned inside bin/mx-test-run.sh. Each script declares the exclusive resources it can touch, such as herdr-session, tmux-server, watcher-process, process-signal, repo-root, or global. Scripts with no shared resource run concurrently up to the job limit; scripts sharing a resource serialize; unclassified scripts receive global and cannot overlap anything.

--all becomes full inventory plus safe automatic concurrency. --jobs N bounds workers, --jobs auto resolves from available CPUs with a conservative cap, and --jobs 1 is the serial reference. Output remains buffered per script and replayed deterministically, while final exit/gate-skip/timing aggregation remains unchanged.

Safety gate

A resource declaration grants concurrency authority, so it must be earned. Extend mx-test-isolation-proof.sh from a flat candidate list to a conflict-matrix proof: run every newly concurrent pairing repeatedly, verify private temp/state roots, verify no leaked processes or backend containers, and archive the exact manifest and results. A flaky or cross-contaminating pair is serialized; it is never retried into the parallel set.

4. Replace elapsed waiting with observable completion

  • Add one bounded mx_test_wait_until helper with short adaptive polling and a diagnostic on timeout; use it for files, process exit, pane state, lock publication, and backend object appearance instead of fixed settle sleeps.
  • For logic whose subject is elapsed time, inject a test-only monotonic-clock command or existing timeout environment knob and advance a fake clock deterministically. Assert the production default value in a separate contract test.
  • Keep one real-time smoke per timing primitive to prove the production path actually blocks and wakes; matrix rows use the fake clock.
  • Replace the real-Herdr AFK suite's 8/10/12-second sleeps with waits for the exact composer, marker, digest, or daemon state it later asserts.
  • Do not shorten a timeout by changing production defaults. A test seam must be inert when its explicit MX_TEST_* input is absent.

5. Reuse setup, never mutable state

Add helpers for immutable git repository templates, activated broker-home templates, and fake toolchain templates. A suite may build each template once, but every case still receives a new directory, independent index/worktree metadata, independent state root, and independent process registry. Reusing a mutable home, live backend pane, watcher lock, queue, or worktree across cases is forbidden unless that persistence is the behavior under test.

6. CI and local execution converge

Replace the hand-maintained two-shard portable lists with duration-balanced scheduler shards generated from the audited manifest and current timing JSON. CI still owns a dedicated real-Herdr job and a coverage guard, but the portable jobs use the same resource declarations and aggregation semantics as local --all. CONTRIBUTING.md documents the fast full command, serial reference, focused/changed loops, performance proof, and the rule that timeout increases are not performance fixes.

Test plan for the test plan

Existing contracts that must keep passing

  • mx-test-run.test.sh: exact inventory, family/changed selection, timing JSON, aggregate failure, gate-skip accounting, coverage guard, and JSON aggregation.
  • mx-test-isolation-proof.test.sh: archived proof parity, explicit serial reasons, CI wiring, and failure propagation under concurrency.
  • Every current behavior suite in serial reference mode; no production suite may be deleted merely because its cases moved into split files.

New contracts

  • Resource scheduler: disjoint resources overlap; shared resources never overlap; global overlaps nothing; unknown scripts fail closed; worker cap is honored.
  • Parity: serial and accelerated modes produce the same per-script exit class, expected-skip class, and named assertion multiset.
  • Failure behavior: multiple concurrent failures are all reported; one worker crash cannot deadlock the queue or erase another result.
  • Cleanup: no test-owned process, tmux server, Herdr lab, lock, temporary directory, or worktree survives either success, failure, or signal interruption.
  • Clock seams: fake time changes only explicit tests; production defaults and one real elapsed-time smoke remain.
  • Performance: three consecutive full runs meet the wall targets with complete timing JSON and zero new skips.

Definition of done

  • The original 96-script inventory is traceable through the new inventory with no lost scenario; split suites include a committed before/after named-assertion map.
  • --check-coverage proves exact inventory once, no duplicates, no omissions.
  • --all --jobs 1 and accelerated --all agree on exits, skips, and assertion labels.
  • The isolation proof passes repeatedly with no cross-test contamination or leaked resources.
  • On the Plan-06 baseline host, three clean accelerated full runs have median wall time ≤15 minutes and maximum wall time ≤18 minutes.
  • After three green main-branch CI runs, behavior critical path is ≤12 minutes; no job timeout was raised to manufacture success.
  • No production behavior or safety timeout changed; documentation and runner help describe the new default and serial escape hatch accurately.

Dependencies & ordering

  • After Plan 06. Its two complete local runs provide the first current Multplx timing baseline and revealed the dormant-contract fixture cost.
  • Before Plan 07. Plans 07–11 add large new behavior surfaces; they should inherit the accelerated runner rather than multiply the current 52-minute feedback loop.
  • No production dependency. This phase may be implemented and reviewed independently of toolbelt, delivery, gate, and workflow behavior.

Risks & open questions

Risk — false green through accidental test weakening

Splitting and clock substitution can silently stop exercising the original entrypoint. Mitigation: archive named assertions before edits, compare serial/accelerated outputs, retain real-time and real-backend smokes, and reject any scenario-count reduction unless a duplicate is proved byte-for-byte and documented.

Risk — concurrency creates flakes

Tests intentionally exercise locks, signals, watchers, tmux, Herdr, and process identity. Mitigation: resource conflicts are explicit and fail closed; newly concurrent pairs require repeated leak-free proof. Speed never outranks determinism.

Decided — performance target and scope

The target is ≤15 minutes locally without reducing behavioral coverage. This plan changes test infrastructure only and must land before Plan 07. There are no product decisions or open questions blocking implementation.
