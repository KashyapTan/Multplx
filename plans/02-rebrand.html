Plan 02 / 10

Full Rebrand — Ship Metaphor Out, Multplx Vocabulary In

Replace every rank-coded nautical term (captain, crewmate, first mate, fleet, ship) with function-coded computer-science vocabulary — maintainer, broker, actor, daemon — and sweep the entire tree: script names (fm- → mx-), env vars (FM_* → MX_*), docs, on-disk paths, log strings, tests, and a genuine rewrite (not find-and-replace) of example_agents.md.

Phase 2 Effort: High Risk: Medium UPDATE_PLAN §7 (7.1–7.4)

Overview

UPDATE_PLAN §7's goal, verbatim in spirit: remove all rank-coded language ("captain outranks crew, no way around that semantically") and replace it with specific, low-collision computer-science terms — deliberately not generic words like "process" or "operator" that would collide constantly with plain descriptions of the implementation. The human's coordinating role does not disappear (still final say on direction and merge approval), but the name for it must not imply command over the agents, and no agent may be framed as ranked above another.

This is three distinct kinds of work bundled into one plan because they must land together atomically:

  • Vocabulary (§7.1): a fixed role table — maintainer, broker, actor, daemon — plus killing the collective nouns ("the system" or "the run" instead of ship/fleet).
  • Voice (§7.3): example_agents.md needs a real rewrite. Hierarchy lives in the verbs ("ensure your crew completes the task without deviation", "report to you"), not just the nouns; a find-and-replace pass would leave commanding language intact wearing new labels.
  • Mechanics (§7.4): a repo-wide rename sweep — ~86 bin/fm-*.sh scripts plus bin/backends/, two .mjs policy files, ~100 test files, every FM_* env var, harness hook/plugin files, docs, on-disk naming conventions, and the log/error strings scripts emit (read by both the maintainer and the actors, so they are part of the theme too).
Project name — Multplx (decided), prefix — mx- (decided)

UPDATE_PLAN §7.2 evaluated name candidates and recommended Multiplex (with suggested prefix mx-). The project was first named Computer, then renamed by the maintainer on 2026-07-27 to Multplx — a stylized form of that original recommendation, which means the mx- prefix (decided in §8.6 and re-confirmed 2026-07-26) now matches the project name exactly. All §7.4 renames and every new script in plans 03–11 use it. Project name, GitHub repository, and local root folder all match: Multplx (the folder was renamed 2026-07-27, with compatibility symlinks — Computer -> Multplx beside the repo and the old encoded path in ~/.claude/projects/ — keeping pre-rename Claude sessions resolving). Nothing should hardcode either folder name.

Effort is High because the sweep touches nearly every file in the tree and because the example_agents.md rewrite is editorial work, not mechanical. Risk is Medium: a rename this broad can silently break script-to-script sourcing, harness hook registrations, and the test runner's hardcoded name maps — mitigated by doing it as one atomic commit gated by a fully green suite on both sides, plus a permanent grep tripwire test. (The once-riskiest corner — the global ~/.grok/hooks/fm-turn-end.json — no longer exists: grok harness support is deleted in plan 01's backend & harness pruning before this sweep runs.)

Target design in Multplx

Role vocabulary (§7.1 — adopted verbatim)

Old termNew termWhy (from §7.1)
Captain (the human)MaintainerA specific, well-understood software term: final say on direction and merge approval — exactly the job — without reading as everyone's boss day to day. Contributors/maintainers is a functional split, not a rank ladder.
First mate (orchestrator agent)BrokerA broker's whole function is arranging exchanges between independent parties, with zero authority over what those parties decide. Deliberately not "dispatcher" or "router" — both would collide constantly with everyday conversation about the actual system.
Crewmate (task agent)ActorBorrowed from the actor model (Erlang/Akka): a fully independent, autonomous unit interacting only via messages — a real named CS concept designed around having no built-in hierarchy, not just a nicer word for "worker."
Secondmate (persistent domain agent)Daemon (unchanged concept)Already the correct term for a long-running background service, and already matches real script names (fm-supervise-daemon.sh) — the least invented option.
Ship / fleetThe system, or just "the run"No single collective noun needed; avoid another word that quietly re-implies a vessel-and-captain structure.
"Your crew" / "assign to crew""the team" / "route to"Verb choice carries hierarchy as much as the noun does (see the §7.3 voice pass).

Explicitly avoided per §7.1: "node" for actors (overloaded — graph node, network node, Node.js) and "root"/"admin" for the maintainer (carries real privilege/authority connotations, reintroducing the rank problem through the side door).

example_agents.md rewrite (§7.3 — a real rewrite, not find-and-replace)

Swapping nouns alone won't fix it: sentences like "ensure your crew completes the task without deviation" or "report to you" carry hierarchy in the verb. A find-and-replace pass would leave commanding language intact wearing new labels. The rewrite must:

  • Reframe the broker's charter from "you supervise and command the crew" to "you coordinate and route work between independent actors" — with authority for direction changes and approvals living with the maintainer, not the broker.
  • Replace command verbs with coordination verbs, systematically:
    Command verb (out)Coordination verb (in)
    assign, instruct, order, directroute, relay to, brief
    ensure compliance, enforce, make sure it obeyscheck in with, verify against the brief, reconcile
    report to (you/the captain)sync with, surface to, relay to the maintainer
    supervise, oversee, commandcoordinate, track, monitor state
  • Remove any "lesser-than" framing — an actor or daemon is an equally capable agent doing a different job in the workflow, not a subordinate.
  • Keep the maintainer's real authority stated plainly and functionally — final call on design/architecture and merge approval — without wrapping it in command language.

Section-level consequences in the copied example_agents.md template: §9 "Escalation and captain etiquette" → maintainer etiquette; §11 "Crewmate briefs" → actor briefs; §8's supervision protocol becomes coordination/monitoring language; §14 is already gone (plan 01). Every skill the file references gets its renamed identity (see inventory).

Grep-driven completeness strategy (§7.4)

§7.4's stated method for full coverage: "grep for captain|crew|mate|ship|fleet|fm_|fm- (case-insensitive) across the whole tree and work through every hit."

# The sweep driver — run repeatedly until the only hits are allowlisted:
grep -rniE 'captain|crew|mate|ship|fleet|fm_|fm-|firstmate|secondmate|crewmate' \
  --exclude-dir=firstmate --exclude-dir=.git --exclude-dir=plans .

# Expect false positives from English words — inspect, don't blind-replace:
#   "mate"  → estimate, ultimate, climate, intimate
#   "ship"  → relationship, ownership, membership, shipping
#   "crew"  → screwed (rare), but check
# Allowlist (never rewritten):
#   firstmate/           - the upstream reference checkout (TEMPORARY: removed
#                          entirely once porting completes, per the 2026-07-26
#                          maintainer decision — drop this allowlist entry then)
#   plans/               - these historical planning docs
#   UPDATE_PLAN.md, firstmate_dependencies.md - historical specs
#   upstream tool names  - "no-mistakes", "lavish-axi", "treehouse" when
#                          describing upstream (per §8.6)

Broker contract & documentation updates

The rebrand is complete only when the broker and all maintained documentation use the Multplx vocabulary and the final mx-* paths consistently.

  • example_agents.md: perform the full role-and-voice rewrite, update every script, environment variable, config, state, and skill reference, and preserve only the future broker's base operating contract.

Risks & open questions

Decided · 2026-07-26

The prefix stays mx-. When the project was still named Computer, the maintainer was indifferent between mx- and alternatives (cpu-/co-/cr-), so the incumbent won: mx- was already locked in UPDATE_PLAN §8.6, switching would mean redoing the entire rename inventory for zero benefit, and the strongest alternative — cr- — reads as "code review". The 2026-07-27 rename to Multplx retroactively vindicates the choice: mx- is the natural abbreviation of the project name. All §7.4 renames and every new script in plans 03–11 use mx-.

Decided 2026-07-28 — mx-actor-state.sh

fm-crew-state.sh becomes mx-actor-state.sh. The explicit role keeps the reconciliation oracle discoverable without the ambiguity of mx-state.sh.

Decided 2026-07-28 — remove residual nautical names

ahoy becomes recap, bearings becomes catchup, and the snapshot helper becomes mx-status-snapshot.sh. This completes the metaphor break while preserving each function.

Risk — string-referenced paths break silently

Script names live as strings in hook JSON/TS/JS files, # shellcheck source= directives, the test runner's case maps, spawn/dispatch commands, and docs. git mv fixes none of those. Mitigations: the §7.4 grep driver run to zero non-allowlisted hits, mx-naming.test.sh, the optional runner-topology test, and a manual smoke of each remaining harness's hook registration (claude/codex/pi — the out-of-repo global ~/.grok/hooks/ file is no longer a concern after plan 01's grok deletion).

Risk — live homes and on-disk state under old names

Any existing firstmate home has config/crew-harness, data/secondmates.md, and state written under old conventions. Multplx is a fresh standalone project, so the default position is no migration shim — fresh homes only. If the maintainer wants to carry an existing home across, a one-shot migration script is a separate follow-up, not part of this sweep.

Risk — grep false positives cause over-replacement

"mate" matches estimate/ultimate/climate; "ship" matches relationship/ownership. The sweep must be hit-by-hit review, never a blind sed. Budget real time for this — it is the bulk of the High effort rating along with the example_agents.md rewrite.
