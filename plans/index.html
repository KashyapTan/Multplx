Multplx · Port Master Plan

Porting firstmate → Multplx

Fifteen ordered implementation plans for turning the upstream firstmate orchestrator into Multplx — a standalone, customized, egress-safe agent-orchestration system with no rank-coded vocabulary and no hard dependencies on the upstream author's tool ecosystem. Plans 01–11 plus Plan 6.5 are the port; plans 12–14 are post-port improvements that don't gate it. Execution order and testing strategy live in porting.md alongside this index.

How to read these plans

Each plan is a self-contained HTML document derived from a section of UPDATE_PLAN.md, grounded against the real firstmate sources in firstmate/. Plans are numbered in recommended execution order — dependencies flow downward. Old vocabulary (captain, crewmate, fleet) appears only when describing upstream firstmate; target designs use the new terms: maintainer (the human), broker (orchestrator agent), actor (task agent), daemon (persistent domain agent). All new scripts carry the mx- prefix.

Phase 1 · Shrink the surface
PLAN 01Delete the Dead Weight — Outright Dependency Removal
Remove the myfirstmate.io X/Discord social relay, GitLab (glab) support, the standalone shellcheck installer/gate, and the macOS osascript wedge alarm — plus the decided backend/harness pruning: drop zellij & orca backends and grok & opencode harnesses (keep tmux, cmux, herdr / claude, codex, pi).

Phase 2 · Rename everything
PLAN 02Full Rebrand — Ship Metaphor Out, Multplx Vocabulary In
maintainer / broker / actor / daemon role vocabulary, a real rewrite of example_agents.md (verbs, not just nouns), and the repo-wide fm-→mx- rename sweep across scripts, env vars, docs, state paths, and log strings.
UPDATE_PLAN §7Effort: HighRisk: Medium
Phase 3 · Harden the core loop
PLAN 03Validated Status Reporting — Enforce the Schema at Write-Time
New mx-report wrapper + MCP report_status tool validate every status line against the closed state enum before it hits disk, so malformed reports fail loudly on the model's own turn instead of silently degrading downstream.
UPDATE_PLAN §3Effort: MediumRisk: Low
PLAN 04Low-Latency Nudge — Wake the Watcher Without a Daemon
mx-report optionally signals the live watcher as a pure fast-path wake; the durable status write happens every time regardless, and with no listener it's a silent no-op back to normal polling. No new persistent process.
UPDATE_PLAN §4Effort: LowRisk: Low
PLAN 05Explicit Signal Precedence in the Classifier
One documented rule in the classify lib for conflicting signals about the same task: harness-native event > schema-validated self-report > text/regex heuristic — applied uniformly across every backend.
UPDATE_PLAN §5Effort: Low–MedRisk: Medium
Phase 4 · Foundation decision
PLAN 06Worktree Provider — Keep Treehouse
Treehouse stays: pinned v2.0.1, SHA-verified, functionally untouched. This phase carries it through the port — rebrand rename of the installer and call sites, an unconditional bootstrap requirement now that orca is gone, and the isolation/lease guarantees plans 09, 10, and 13 depend on. Build-our-own designs were removed from the plan (git history only).
UPDATE_PLAN §1 + §8Effort: LowRisk: LowDecided: keep
Phase 4.5 · Accelerate the proof loop
PLAN 6.5Test Suite Acceleration — Same Proof, Much Shorter Wait
Cut the measured 52.1-minute local full regression to 15 minutes or less without deleting scenarios, weakening assertions, adding skips, or shrinking production timeouts. Split oversized suites at proved isolation boundaries, replace fixed waits with observable conditions and fake clocks, reuse immutable fixtures, and schedule the full inventory through an audited resource-conflict manifest.
Maintainer request · 2026-07-28Effort: HighRisk: Medium
Phase 5 · Own the toolbelt
PLAN 07Owning the Toolbelt — Replacing the -axi Dependencies
gh-axi collapses to the official gh CLI; tasks-axi becomes an in-repo markdown backlog lib; quota-axi becomes our composite local-resource plus configured-API-budget headroom check; chrome-devtools-axi is deferred out.
UPDATE_PLAN §8.2Effort: MediumRisk: Medium
PLAN 08vplan — Plan Artifacts with an In-Page Review Loop
Our replacement for lavish-axi, redesigned 2026-07-27: the broker authors a diagram-rich HTML plan, mx-vplan.sh serves it on loopback with an injected comment overlay, the maintainer annotates any element, and one confirm writes the comments into the file itself and shuts the server down. Ports lavish's authoring playbooks; drops its daemon, polling, and hosting machinery.
UPDATE_PLAN §8.5Effort: MediumRisk: Low
Phase 6 · Safe delivery
PLAN 09Least-Privilege Push — Agents Never Hold Remote Credentials
Actors commit locally only; a separate non-agent process with its own service credentials owns git push and PR-open, triggered only after validation passes and the maintainer approves.
UPDATE_PLAN §2Effort: MediumRisk: Medium
Phase 7 · The flagship gate
PLAN 10deep-review — the Local, Egress-Safe Validation Gate
Replaces the upstream no-mistakes tool with an in-repo pipeline (mx-deep-review.sh) run by the already-approved harness: fixed step order, schema-forced findings, deterministic gate decisions, default-branch-only command trust, delivery stopping at a validated local branch.
UPDATE_PLAN §6 + §8.6Effort: HighRisk: High
Phase 8 · Compose everything
PLAN 11Workflow Engine — Deterministic Skeleton, Model-Driven Interior
User-defined, repeatable multi-stage workflows: one shared engine (mx-workflow.sh) enforces stage order, gates (approve/auto), and output contracts from schema-validated definition files, while the model does the judgment work inside each stage. Includes the create-workflow skill — the broker interviews the maintainer and authors new definitions itself.
New feature (maintainer request)Effort: HighRisk: Medium
Phase 9 · Post-port improvements (don't gate the port)
PLAN 12mx-journal — One Timeline per Task
An append-only observability journal every writer also emits to (spawns, status transitions, classification verdicts with the winning signal tier, gate rounds, decisions, workflow stages, delivery). mx-timeline <id> reconstructs any task's life in one command. Never read for control flow — the scattered state files remain the operational truth.
Post-port (maintainer request)Effort: MediumRisk: Low
PLAN 13mx-doctor — One Command to Check Every Invariant
A read-only health sweep of every system invariant (stale locks, orphaned worktrees, dead PIDs, dangling queue entries, open holds with no task, tool/auth presence, compat-symlink health) with a whitelisted --fix mode for provably-safe cleanups. Reuses bootstrap's probe logic via a shared check lib.
Post-port (maintainer request)Effort: Low–MedRisk: Low
PLAN 14Upstream Sync — Don't Fork and Forget
A fork-point record, a subsystem relevance map, and a review-and-reimplement procedure so upstream firstmate bug fixes to kept mechanisms still reach Multplx. Shipped as a workflow definition for the plan-11 engine — its first recurring consumer. Includes an explicit retirement path when triage stops paying for itself.
Post-port (maintainer request)Effort: LowRisk: Low
